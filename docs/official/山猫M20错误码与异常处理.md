## 1. 设备异常状态上报

basic_server 以 **2Hz** 固定频率向心跳来源 IP/端口主动上报；当异常发生或解除时，会额外立即上报一次。

| Type 字段值 | Command 字段值 | 消息类型 |
|---|---|---|
| 1002 | 3 | 获取异常状态信息 |

> **文档中出现的所有 Type / Command 均为十进制数字。**

### JSON 格式响应

```json
{
  "PatrolDevice": {
    "Type": 1002,
    "Command": 3,
    "Time": "2023-01-01 00:00:00",
    "Items": {
      "ErrorList": [
        {
          "errorCode": 32769,
          "component": 1
        },
        {
          "errorCode": 33026,
          "component": 0
        }
      ]
    }
  }
}
```

### XML 格式响应

```xml
<?xml version="1.0" encoding="UTF-8"?>
<PatrolDevice>
  <Type>1002</Type>
  <Command>3</Command>
  <Time>2023-01-01 00:00:00</Time>
  <Items>
    <ErrorList>
      <errorCode>32769</errorCode>
      <component>1</component>
    </ErrorList>
    <ErrorList>
      <errorCode>33026</errorCode>
      <component>0</component>
    </ErrorList>
  </Items>
</PatrolDevice>
```

一次响应可能包含多组 ErrorList，每组 ErrorList 包含以下参数项：

| 参数项 | 含义 | 数据类型 | 单位 | 参数值说明 |
|---|---|---|---|---|
| errorCode | 错误码 | int | - | 详见错误码表 |
| component | 发生错误的部件位置信息 | int | - | 以 bit 位作为部件号 |

### component 部件号说明

当关节或电池发生异常时，component 用于确定发生异常的具体关节或电池。

**关节编号：** 按照 FL/FR/BL/BR + HipX/HipY/Knee/Wheel 的顺序从低位到高位进行编号，例如 0x21（0000 0000 0010 0001）则表示：
- 第 0 位（LeftFrontHipX 关节）出现错误
- 第 5 位（RightFrontHipY 关节）出现错误

**电池编号：**
- 第 0 位：后侧电池（靠近硬急停按钮的一侧）
- 第 1 位：前侧电池

## 2. 导航任务异常上报

### 2.1 请求响应方式

开发者下发导航任务后可获取响应消息，消息中携带导航任务异常码。  
或可通过查询导航任务状态，响应消息中携带导航任务异常码。

### 2.2 主动上报（软件包版本 ≥V1.1.8）

basic_server 以 **1Hz** 固定频率向心跳来源 IP/端口主动上报。

| Type 字段值 | Command 字段值 | 消息类型 |
|---|---|---|
| 1007 | 3 | 获取导航任务异常状态信息 |

#### JSON 示例

```json
{
  "PatrolDevice": {
    "Type": 1007,
    "Command": 3,
    "Time": "2023-01-01 00:00:00",
    "Items": {
      "NavStatus": {
        "Value": 0,
        "Status": 0,
        "ErrorCode": 0,
        "LoopCnt": 0,
        "RemainingCnt": 0,
        "Name": "XXX"
      },
      "LocationStatus": {
        "Location": 1,
        "PosX": 0.0,
        "PosY": 0.0,
        "PosZ": 0.0,
        "Roll": 0.0,
        "Pitch": 0.0,
        "Yaw": 0.0
      }
    }
  }
}
```

#### NavStatus 字段说明

| 参数项 | 含义 | 数据类型 | 单位 | 参数值说明 |
|---|---|---|---|---|
| Value | 导航任务目标点变化 | int | - | 与下发导航任务请求对应 |
| Status | 导航任务执行状态 | int | - | 见后表 |
| ErrorCode | 错误码 | int | - | 见 2.3 节 |
| LoopCnt | 循环次数 | uint | - | - |
| RemainingCnt | 循环剩余次数 | uint | - | - |
| Name | 导航任务名称 | string | - | - |

#### NavStatus.Status 导航任务执行状态

| 参数值（十进制） | 参数值（十六进制） | 含义 |
|---|---|---|
| 0 | 0x0 | 空闲 |
| 1 | 0x1 | 退出充电桩中 |
| 2 | 0x2 | 导航预处理 |
| 3 | 0x3 | 导航中 |
| 4 | 0x4 | 导航完成 |
| 5 | 0x5 | 进入充电桩中 |
| 255 | 0xFF | 暂停中 |

#### LocationStatus 字段说明

| 参数项 | 含义 | 数据类型 | 单位 | 参数值说明 |
|---|---|---|---|---|
| Location | 定位状态 | int | - | 0：定位正常；1：定位丢失 |
| PosX/Y/Z | 机器人在地图坐标系下的坐标 | float | m | - |
| Roll/Pitch/Yaw | 机器人在地图坐标系下的姿态角度 | float | rad | - |

## 3. 通讯错误码机制

basic_server 在收到客户端下发的每一个请求后，都会返回该条消息。

### JSON 形式

```json
{
  "PatrolDevice": {
    "Type": XXXX,
    "Command": XX,
    "Time": "2023-01-01 00:00:00",
    "Items": {
      "ErrorCode": 0,
      "ErrorMessage": "Success"
    }
  }
}
```

### XML 形式

```xml
<?xml version="1.0" encoding="UTF-8"?>
<PatrolDevice>
  <Type>XXXX</Type>
  <Command>XX</Command>
  <Time>2023-01-01 00:00:00</Time>
  <Items>
    <ErrorCode>0</ErrorCode>
    <ErrorMessage>Success</ErrorMessage>
  </Items>
</PatrolDevice>
```

其中，回复的 Type 和 Command 字段值与客户端下发的对应请求消息中的 Type 和 Command 字段值相同。

### 通用通讯错误码表

| ErrorCode（十六进制） | ErrorCode（十进制） | ErrorMessage | 含义/建议动作 |
|---|---|---|---|
| 0x0000 | 0 | Success | 发送成功，可继续下一步 |
| 0xE001 | 57345 | Unsupported data format | 发送的数据格式不支持（非 XML 和 JSON），建议检查帧头 Format 字段 |
| 0xE002 | 57346 | Data parsing failed | 协议格式异常，数据解析失败，缺少 PatrolDevice、Items、Type、Command，建议校验 JSON/XML 格式 |
| 0xE003 | 57347 | Unsupported protocol type | 找不到 Type、Command 对应的协议，建议检查 Type、Command 值 |
| 0xE004 | 57348 | Missing necessary fields | 缺少协议字段 |
| 0xE005 | 57349 | Mismatched data type | 字段类型不匹配，建议校对字段类型 |
| 0xE006 | 57350 | Mismatched request client | 请求客户端不匹配，例如：轴指令发送时，要求 2s 内发送的指令来自同一个客户端 |
| 0xE007 | 57351 | No operation permission | 无操作权限 |
| 0xE008 | 57352 | Not allowed operation | 当前状态下不允许的操作，建议检查状态机（如未站立不能发速度） |
| 0xE009 | 57353 | Operation failure | 操作失败，建议查看 Type=1002, Cmd=3 错误详情 |
| 0xE00A | 57354 | Unsupported function | 不支持的功能，例如：导航功能只有 Pro 版本支持，建议确认固件版本 |
| 0xE00B | 57355 | Internal error | 内部错误，如内部文件打开失败，内部文件解析失败等，建议查看日志 |

> **注意：** ErrorCode=0x0000 仅表示命令已被接收并触发，不代表业务执行成功。

## 4. 异常处理建议

### 4.1 设备异常处理流程

```
1. 监控 Type=1002, Cmd=3 的 ErrorList
2. 解析 errorCode 和 component 字段
3. 根据错误码表确定异常类型
4. 针对具体异常进行处理：
   - 电机/关节异常：检查关节状态，必要时重启机器人
   - 电池异常：检查电量，更换电池或停止任务
   - CPU 异常：检查系统负载，关闭不必要的进程
   - 自主充电异常：执行重置指令（Charge=2）
```

### 4.2 导航异常处理流程

```
1. 监控导航任务响应中的 ErrorCode
2. 或订阅 Type=1007, Cmd=3 的主动上报
3. 解析 NavStatus 和 LocationStatus 字段
4. 根据错误码表确定异常类型
5. 针对具体异常进行处理：
   - 定位丢失：执行定位重置（Type=2101, Cmd=1）
   - 任务失败：取消当前任务，重新规划路径
   - 模块异常：检查相关服务是否存活
```

### 4.3 Python 示例

```python
# 解析设备异常状态
def parse_error_list(error_list):
    """
    解析错误列表
    :param error_list: Type=1002 Cmd=3 的 Items.ErrorList
    :return: 异常字典列表
    """
    errors = []
    for item in error_list:
        error_code = item.get("errorCode")
        component = item.get("component")
        errors.append({
            "error_code": error_code,
            "component": component,
            "description": get_error_description(error_code)
        })
    return errors

# 解析导航异常状态
def parse_nav_error(nav_status):
    """
    解析导航异常状态
    :param nav_status: Type=1007 Cmd=3 的 NavStatus
    :return: 导航异常信息
    """
    return {
        "task_value": nav_status.get("Value"),
        "task_status": nav_status.get("Status"),
        "error_code": nav_status.get("ErrorCode"),
        "loop_count": nav_status.get("LoopCnt"),
        "remaining_count": nav_status.get("RemainingCnt"),
        "task_name": nav_status.get("Name")
    }

# 错误码描述映射表
ERROR_CODE_DESCRIPTIONS = {
    32769: "电机温度预警",
    32770: "电机温度过高保护",
    32771: "电机温度致命截止",
    33026: "低电量预警",
    33027: "保护电量",
    # ... 更多错误码
}

def get_error_description(error_code):
    return ERROR_CODE_DESCRIPTIONS.get(error_code, "未知错误")
```

### 5.1 关节/电机异常（0x80xx）

|---|---|---|
| 0x8001 | 电机温度预警 | 电机过热 |
| 0x8002 | 电机温度过高保护 | 电机过热，已保护停机 |
| 0x8003 | 电机温度致命截止 | 电机严重过热 |
| 0x8007 | 关节驱动器过温 | 驱动器过热 |
| 0x8012 | 与关节驱动器通讯超时 | 通讯中断 |
| 0x8020 | 驱动器过流保护 | 电流过大 |
| 0x8022 | 关节角超限 | 机械限位触发 |

### 5.2 电池异常（0x81xx）

| 错误码 | 含义 | 可能原因 |
|---|---|---|

| 0x8103 | 保护电量 | 电量过低，进入保护 |
| 0x8122 | 短路保护 | 电路短路 |
| 0x8124 | 电池软件锁定 MOS | 电池管理系统锁定 |

### 5.3 CPU/系统异常（0x82xx）

| 错误码 | 含义 | 可能原因 |
|---|---|---|
| 0x8201 | CPU 占用率过高预警 | 系统负载高 |

| 0x8211 | CPU 占用率过高保护 | CPU 过载保护 |

| 错误码 | 含义 | 处理建议 |
