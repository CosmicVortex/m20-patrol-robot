## 前置说明

自主充电是巡检系统的核心闭环。

在导航任务过程中执行自主充电，请参考 [导航任务下发](./navigation-tasks.md) 中的单点任务下发指令，以**充电点**形式下发即可。

本章仅说明直接调用自主充电功能（需确保机器人已到达充电桩前）的使用细节，并提供 basic_server、ROS2 等多种接入方式。

> **自主充电为选配功能。**

相关文档：[basic_server 通信协议总览](./basic-server-protocol-overview.md) | [ROS 2 / DDS 接口总览](./ros2-dds-overview.md)

## 1. 系统架构

### 1.1 数据流

```
业务后台
  │
  │  Type=2 Cmd=24
  ▼
basic_server
  │ DRDDS → /CHARGE
  ▼
charge_manager
  │  调度 reflective_column_node
  │  切换进退桩步态，规划进退桩路径，下发进退桩速度
  ▼
rl_deploy → 电机
```

#### 组件职责

| 组件 | 主机 | 职责 |
|---|---|---|
| reflective_column_node | NOS | 雷达点云识别充电桩反光柱 |
| charge_manager | NOS | 充电状态机、上下桩调度 |
| basic_server | AOS | 接收业务层指令、转发速度指令 |
| rl_deploy | AOS | 步态执行 |

### 1.2 状态机

开发时务必遵循上述状态流转逻辑，部分异常情况下可能需要人工介入将机器狗搬离充电桩后再继续下一步操作。

| 指令值 | 指令名称 | 指令作用 |
|---|---|---|
| 1 | 开始充电 | 空闲状态下，执行进桩趴下充电 |
| 0 | 退出充电 | 从充电状态退出，回到桩前位置 |
| 2 | 重置 | 强制切断充电电流、强制状态归零、同时清除相关错误记录 |

#### 调用逻辑建议

- 自主充电进入异常状态后，**必须下发重置指令才能继续使用**。
- 进退桩过程中：具备停障保护，若停障超过 **30 秒**，则会进入异常状态。

#### 自主充电相关异常码

可通过 basic_server 协议 **Type=1002, Cmd=3** 获取：

| 异常码（十六进制） | 异常码（十进制） | 异常说明 |
|---|---|---|
| 0x8501 | 34049 | 自主充电获取反光柱定位数据超时 |
| 0x8502 | 34050 | 自主充电反光柱定位算法开启失败 |
| 0x8503 | 34051 | 未检测到反光柱 |
| 0x8506 | 34054 | 自主充电充电桩无电流 |
| 0x8507 | 34055 | 充电进退桩过程中停障超时 |
| 0x8509 | 34057 | 自主充电进桩失败 |
| 0x8510 | 34064 | 自主充电退桩失败 |

## 2. 充电指令下发

### 2.1 basic_server 协议（Type=2, Command=24）

#### JSON 请求

```json
{
  "PatrolDevice": {
    "Type": 2,
    "Command": 24,
    "Time": "2026-05-20 10:00:00",
    "Items": {
      "Charge": 1
    }
  }
}
```

#### XML 等价

```xml
<?xml version="1.0" encoding="UTF-8"?>
<PatrolDevice>
  <Type>2</Type>
  <Command>24</Command>
  <Time>2026-05-20 10:00:00</Time>
  <Items>
    <Charge>1</Charge>
  </Items>
</PatrolDevice>
```

#### 字段说明

| 字段 | 类型 | 取值 | 含义 |
|---|---|---|---|
| Charge | int | 0 | 退出充电 — 停止当前充电并退桩 |
| Charge | int | 1 | 开始充电 — 启动自主充电流程 |
| Charge | int | 2 | 重置 — 强制恢复空闲状态 |

> **⚠️ 警告：** Charge=2 为强制清除充电状态操作，存在风险。建议仅在充电状态异常且无法正常结束充电时使用。正常使用应通过 Charge=0 结束充电。

### 2.2 ROS2 接口

| 话题名称 | 消息格式 |
|---|---|
| `/CHARGE` | drdds/msg/StdMsgInt32 |

drdds/msg/StdMsgInt32 为自定义消息类型：
```
int32 value
```

| value 值 | 含义/对应指令 |
|---|---|
| 1 | 开始充电 |
| 0 | 退出充电 |
| 2 | 重置 |

> **注意：** 目前仅能在 33 网段的 AOS 主机和 NOS 主机上访问该话题。

## 3. 充电状态推送

### 3.1 basic_server 协议（Type=1002, Command=6）

```json
{
  "PatrolDevice": {
    "Type": 1002,
    "Command": 6,
    "Time": "2023-01-01 00:00:00",
    "Items": {
      "BasicStatus": {
        "MotionState": 0,
        "Gait": 0,
        "Charge": 0,
        "HES": 0,
        "ControlUsageMode": 0,
        "Direction": 0,
        "OOA": 0,
        "PowerManagement": 0,
        "Sleep": 0,
        "Version": "STD"
      }
    }
  }
}
```

#### Charge 字段说明

| Charge | 含义 |
|---|---|
| 0 | 空闲 |
| 1 | 进桩中 |
| 2 | 充电中 |
| 3 | 退桩中 |
| 4 | 异常 |
| 5 | 在桩未充电 |

### 3.2 ROS2 接口

| 话题名称 | 消息格式 |
|---|---|
| `/CHARGE_STATUS` | drdds/msg/StdStatus |

drdds/msg/StdStatus 为自定义消息类型：
```
int32 state
uint32 error_code
```

#### state 值定义

| state | 含义 |
|---|---|
| 0 | 空闲 |
| 1 | 前往电桩过程中 |
| 2 | 充电中 |
| 3 | 退出电桩过程中 |
| 4 | 机器人异常 |
| 5 | 在桩上但无电流 |
| 6 | 空闲（重置操作 / 初始化） |

#### error_code 值定义（仅当 state=4 时有意义）

| error_code（十六进制） | error_code（十进制） | 含义 |
|---|---|---|
| 0x0000 | 0 | 空闲状态 |
| 0x0001 | 1 | 正常运行中 |
| 0x1002 | 4098 | 自主充电获取反光柱定位数据超时 |
| 0x1003 | 4099 | 自主充电反光柱定位算法开启失败 |
| 0x1004 | 4100 | 未检测到反光柱 |
| 0x1005 | 4101 | 自主充电进桩失败 |
| 0x1006 | 4102 | 自主充电退桩失败 |
| 0x1007 | 4103 | 自主充电充电桩无电流 |
| 0x1008 | 4104 | 软急停 |
| 0x1009 | 4105 | 充电进桩过程中触发停障 |
| 0x100A | 4106 | 充电退桩过程中触发停障 |

> **注意：** 仅当 state = 4 或 5 时才是异常状态。特殊情况下，比如 error_state = 0x1009 或 0x100A 时，可能只是短时间触发停障，不一定会导致超时失败；需要结合 state 的值来判断是否处于异常。

> **注意：** 目前仅能在 33 网段的 AOS 主机和 NOS 主机上访问该话题。

## 4. 开发建议

### 4.1 正常充电流程

```
1. 确保机器人已到达充电桩前（通过导航任务下发充电点）
2. 发送 Type=2, Cmd=24, Charge=1 开始充电
3. 监控 Type=1002, Cmd=6 的 Charge 字段
   - Charge=1: 进桩中
   - Charge=2: 充电中
   - Charge=3: 退桩中
   - Charge=0: 空闲（充电完成）
4. 充电完成后，可再次发送 Charge=1 开始下一轮充电
```

### 4.2 异常处理流程

```
1. 监控 /CHARGE_STATUS 话题或 Type=1002, Cmd=3 错误列表
2. 检测到异常（state=4 或 Charge=4）时：
   a. 记录 error_code 或 ErrorCode
   b. 发送 Charge=2 重置
   c. 等待机器人恢复空闲状态（Charge=0 或 state=6）
   d. 重新发起充电流程
```

### 4.3 Python 示例

```python
import json
from datetime import datetime

def build_charge_command(charge_value):
    """
    发送充电指令
    :param charge_value: 1=开始充电, 0=退出充电, 2=重置
    """
    return {
        "PatrolDevice": {
            "Type": 2,
            "Command": 24,
            "Time": datetime.now().strftime("%Y-%m-%d %H:%M:%S"),
            "Items": {"Charge": charge_value}
        }
    }

def parse_charge_status(basic_status_items):
    """
    解析充电状态
    :param basic_status_items: Type=1002 Cmd=6 的 Items 字段
    :return: charge_state, description
    """
    charge = basic_status_items.get("BasicStatus", {}).get("Charge", 0)
    state_map = {
        0: "空闲",
        1: "进桩中",
        2: "充电中",
        3: "退桩中",
        4: "异常",
        5: "在桩未充电"
    }
    return charge, state_map.get(charge, "未知")
```

## 5. 注意事项

1. **前置条件：** 调用自主充电前，需确保机器人已到达充电桩前（可通过导航任务下发充电点实现）。
2. **异常恢复：** 进入异常状态后，必须下发重置指令（Charge=2）才能继续使用。
3. **停障保护：** 进退桩过程中停障超过 30 秒会进入异常状态。
4. **重置风险：** Charge=2 为强制清除操作，可能影响数据记录，建议仅在异常时使用。
5. **导航集成：** 正常巡检流程中，推荐使用导航任务下发充电点的方式，由系统自动调度充电。
