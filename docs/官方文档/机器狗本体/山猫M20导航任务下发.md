## 1. 导航任务功能处理逻辑

### 1.1 下发导航任务后的 basic_server 内部流转

当业务层通过 basic_server 协议下发导航任务时，内部处理流程如下：

1. **接收任务**：basic_server 监听 UDP 30000 或 TCP 30001，接收 Type=1003 Cmd=1 报文，提取所有字段。
2. **下发目标点给导航规划**：basic_server 将点位坐标与地图信息（PosX, PosY, PosZ, AngleYaw, MapID）发布到 DDS 服务：
   - 采用直线导航的点位，仅发布到 `/GOAL_PLANNER`，NOS 上的 planner 订阅后进行局部路径规划；
   - 采用自主导航模式的点位，会同时发布到 `/GOAL_GLOBAL` 和 `/GOAL_PLANNER`，NOS 上的 global_planner 和 planner 订阅后进行全局和局部路径规划。
3. **下发步态与模式给运动控制**：basic_server 将运动控制相关参数（Gait 等）下发给 rl_deploy，完成步态切换。
4. **转发规划结果**：planner 规划完成后输出速度指令，basic_server 接收并转发给 rl_deploy 执行最终运动。

#### 模块依赖关系

| 下游模块 | 依赖上游 | 说明 |
|---|---|---|
| localization | rslidar_node + yesense_node | 雷达或 IMU 任一断流，定位失效 |
| planner | localization + passable_area + global_planner | Warning 1001=缺地图，1002=缺定位 |
| passable_area | lio_perception（累积点云） | 导航任务下发后 basic_server 才触发累积点云计算 |
| global_planner | 预建栅格地图 | 不依赖实时传感器 |
| charge_manager | reflective_column_node + /LIDAR/POINTS | 反光柱定位失败则无法进退桩 |
| basic_server | planner | 转发速度指令给 rl_deploy |

### 1.2 planner 依赖数据链路

planner 依赖多个子服务协同工作，数据从传感器采集到最终速度指令输出经过以下流转：

#### 累积帧模式

```
/LIDAR/POINTS + /IMU
    ↓
lio_perception → /LIO_ODOM, /ALIGNED_POINTS, /HEIGHT_IMAGE
    ↓
累积点云 → /accumulate_cloud/cloud_gravity
    ↓
passable_area → /impassable_area
    ↓
planner → /NAV_CMD
```

#### 单帧点云模式

```
/LIDAR/POINTS + /IMU
    ↓
lio_perception → /LIO_ODOM, /ALIGNED_POINTS, /HEIGHT_IMAGE
    ↓
累积点云 → /accumulate_cloud/cloud_gravity
    ↓
planner → /NAV_CMD
```

累积帧模式和单帧点云模式为互斥选项，同时只能开启一个，可在 NOS 主机 `/opt/robot/share/planner/scripts/local_planner.sh` 脚本文件中修改：

```bash
# 接可通行域    确认话题 /impassable_area 是否有效存在
# sudo chrt 50 taskset -c 4,5 $SCRIPT_PATH/../bin/pcl_remove &

# 接普通点云    确认话题 /LIDAR/POINTS 是否有效存在
sudo chrt 50 taskset -c 4,5 $SCRIPT_PATH/../bin/pcl_pass_grid &

sudo chrt 50 taskset -c 4,5 $SCRIPT_PATH/../bin/localPlanner
```

- 如使用累积帧模式，则注释 `sudo chrt 50 taskset -c 4,5 $SCRIPT_PATH/../bin/pcl_pass_grid &`；
- 如使用单帧点云模式，则注释 `sudo chrt 50 taskset -c 4,5 $SCRIPT_PATH/../bin/pcl_remove &`。

> **注意：** 两种模式必须二选一，不能同时注释或取消注释。编辑后请注意保存文件并重启整机以确保新的配置生效。

**调用建议：**
- 如果使用场景中存在较多空旷环境且有较多动态障碍物在导航路线上经过，则建议使用单帧点云模式；
- 如果有较多转弯窄道的环境或有较多动态障碍物横向侵入导航路线，可能从机器狗侧面发生碰撞，则建议使用累积帧模式。

#### 关键内部话题

| 话题 | 说明 | 坐标系 |
|---|---|---|
| `/accumulate_cloud/cloud_gravity` | 重力对齐累积点云 | base_gravity |
| `/impassable_area` | 可通行域/障碍物地图 | base_gravity |
| `/NAV_POINTS` | 导航障碍物点云 | base_link |
| `/grid_map_3d` | 3D 栅格地图 | map |

## 3. 单点导航（Type=1003 Cmd=1）

用户可通过该请求下发导航任务，即前往一个目标点并在目标点执行用户设置的任务。

**机器人收到该请求后，将会先执行导航任务（成功/失败/取消），然后才会发送携带执行结果的响应消息给客户端。**

### 3.1 请求

#### JSON 请求

```json
{
  "PatrolDevice": {
    "Type": 1003,
    "Command": 1,
    "Time": "2023-01-01 00:00:00",
    "Items": {
      "Value": 0,
      "MapID": 0,
      "PosX": 0.0,
      "PosY": 0.0,
      "PosZ": 0.0,
      "AngleYaw": 0.0,
      "PointInfo": 0,
      "Gait": 0,
      "Speed": 0,
      "Manner": 0,
      "ObsMode": 0,
      "NavMode": 0
    }
  }
}
```

#### XML 请求

```xml
<?xml version="1.0" encoding="UTF-8"?>
<PatrolDevice>
  <Type>1003</Type>
  <Command>1</Command>
  <Time>2023-01-01 00:00:00</Time>
  <Items>
    <Value>0</Value>
    <MapID>0</MapID>
    <PosX>0.0</PosX>
    <PosY>0.0</PosY>
    <PosZ>0.0</PosZ>
    <AngleYaw>0.0</AngleYaw>
    <PointInfo>0</PointInfo>
    <Gait>0</Gait>
    <Speed>0</Speed>
    <Manner>0</Manner>
    <ObsMode>0</ObsMode>
    <NavMode>0</NavMode>
  </Items>
</PatrolDevice>
```

> **注意：** 导航任务参数项，按照类型分为点属性参数项和路径属性参数项。点属性是定义导航目标点的属性，包括目标点编号 Value、类型 PointInfo、位置 PosX/PosY/PosZ、朝向 AngleYaw；路径属性是在前往导航目标点的路径中生效的属性，用于规定机器狗应该如何从当前位置走到目标点，包括到达目标点的过程中使用的步态 Gait、速度 Speed、运动朝向 Manner、导航方式 NavMode，以及到达目标点过程中是否开启停避障 ObsMode。

#### 参数项定义

| 参数项 | 含义 | 数据类型 | 单位 | 参数值说明 |
|---|---|---|---|---|
| Value | 导航任务目标点编号 | int | - | 使用默认值 0 |
| MapID | 目标点所在栅格地图编号 | int | - | 使用默认值 0 |
| PosX/PosY/PosZ | 目标点在地图坐标系中的位置坐标 | float | m | - |
| AngleYaw | 目标点在地图坐标系中的朝向 | float | rad | - |
| PointInfo | 目标点类型 | int | - | 过渡点 = 0, 任务点 = 1, 充电点 = 3 |
| Gait | 到达目标点的过程中使用的步态 | int | - | 平地(敏捷) = 0x3002, 楼梯(敏捷) = 0x3003 |
| Speed | 到达目标点的过程中使用的速度 | int | - | 正常 = 0, 低速 = 1, 高速 = 2 |
| Manner | 到达目标点的过程中使用的运动方式 | int | - | 前进行走 = 0, 倒退行走 = 1 |
| ObsMode | 停避障功能 | int | - | 开启 = 0, 关闭 = 1 |
| NavMode | 导航方式 | int | - | 直线导航 = 0, 自主导航 = 1 |

#### 目标点类型说明

| 类型 | 值 | 说明 |
|---|---|---|
| 过渡点 | 0 | 仅用于克服地形和约束路径，到点精度较低 |
| 任务点 | 1 | 到点精度较高，到达后停止运动并保持原地站立，直至收到下一个目标点请求 |
| 充电点 | 3 | 用于识别定位充电桩反光柱，到达后自动进入充电桩充电，保持充电状态直至收到下一个目标点请求 |

#### 步态说明

| 步态 | 值 | 说明 |
|---|---|---|
| 平地步态（敏捷运动模式） | 0x3002 | 适用于平地、草地等地形，支持攀爬 ≤30° 的斜坡 |
| 楼梯步态（敏捷运动模式） | 0x3003 | 适用于通过斜坡（≤30°）和楼梯（≤25cm）等障碍地形 |

#### 导航方式说明

| 导航方式 | 值 | 说明 |
|---|---|---|
| 直线导航 | 0 | 使用直线导航攀爬楼梯时，建议将目标点标到距离最后一阶楼梯边缘 45cm 以外，并关闭导航的停避障功能 |
| 自主导航 | 1 | 应根据地形复杂度设置路径点，地形复杂度越高应设置更密集的路径点。自主导航仅支持平地步态与低速模式。尽量使用多段直线导航代替自主导航 |

#### 停避障说明

当导航的停避障功能开启时：
- 直线导航：表现为停障
- 自主导航：表现为避障

### 3.2 响应

#### JSON 响应

```json
{
  "PatrolDevice": {
    "Type": 1003,
    "Command": 1,
    "Time": "2023-01-01 00:00:00",
    "Items": {
      "Value": 0,
      "Status": 0,
      "ErrorCode": 0
    }
  }
}
```

#### XML 响应

```xml
<?xml version="1.0" encoding="UTF-8"?>
<PatrolDevice>
  <Type>1003</Type>
  <Command>1</Command>
  <Time>2023-01-01 00:00:00</Time>
  <Items>
    <Value>0</Value>
    <Status>0</Status>
    <ErrorCode>0</ErrorCode>
  </Items>
</PatrolDevice>
```

#### 响应字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| Value | int | 导航任务目标点编号，与请求对应 |
| Status | int | 导航任务执行状态（见下表） |
| ErrorCode | int | 错误码（见第 6 节错误码表） |

#### Status 值说明

| Status（十六进制） | 含义 |
|---|---|
| 0x0 | 空闲 |
| 0x1 | 退出充电桩中 |
| 0x2 | 导航预处理 |
| 0x3 | 导航中 |
| 0x4 | 导航完成 |
| 0x5 | 进入充电桩中 |
| 0xff | 暂停中 |

### 3.3 调用建议

- 收到单点导航任务后，机器人会自动切换至导航模式并起立。
- 若用户在导航过程中手动切换至常规/辅助模式，或出现任意异常，导航任务立即结束。
- **导航空闲超时**：若 5 分钟（默认值）无消息，机器人自动趴下。
- **下发条件**：定位状态正常（warning_state == 0）且当前无其他导航任务（或先取消当前任务）。

## 6. 导航错误码（ErrorCode）

导航任务响应（Type=1003 Cmd=1）和状态查询（Type=1007 Cmd=1）中的 ErrorCode 字段含义如下。同一错误码在协议响应和 UI Toast 提示中的描述可能略有差异。

| 0x0000 | 导航任务正常状态 |

| 0x8605 | 移动到点超时 |
| 0xA301 | 运动状态异常，任务失败（软急停、摔倒） |
| 0xA302 | 电量低于 20%，任务失败 |
| 0xA303 | 电机过温异常，任务失败 |
| 0xA305 | 雷达异常（未开启或无点云数据） |
| 0xA312 | 导航模块通讯异常，无法下发任务 |
| 0xA313 | 定位状态持续异常（超过 30s） |
| 0xA314 | 地形图异常 |
| 0xA327 | 步态异常，未切换到目标步态 |
| 0xA328 | 当前不在导航模式，无法执行导航任务 |
| 0xA341 | 当前正在执行任务，下发新任务失败 |
| 0xA343 | 退出自主充电执行失败 |
| 0xA344 | 自主充电异常 |
| 0xA345 | 自主充电执行失败 |
| 0xA349 | 切换地图失败 |
| 0xA34B | 持续停障异常，导航失败 |
| 0xA34C | 局部导航规划失败 |
| 0xA34D | 持续导航速度未刷新，导航失败 |
| 0xA34E | 自主充电流程中，下发任务失败 |
| 0xA400 | 发送目标点到局部导航失败 |
| 0xA401 | 发送目标点到全局导航失败 |
| 0xA402 | 取消局部导航失败 |

## 7. 开发建议

1. 下发导航前确认定位状态正常。
2. 尽量使用多段直线导航代替自主导航，降低路径执行风险。
3. 自主导航时根据地形复杂度设置足够密集的路径点。
4. 攀爬楼梯建议使用直线导航，目标点标到距最后一阶边缘 45cm 以外，关闭导航停避障。
5. 敏捷运动模式下的步态速度响应性能较好，适用于导航等自主算法开发。
6. 若导航任务无法执行，检查导航程序是否启动、各依赖服务是否存活。

## 8. 代码示例

### Python 示例

```python
import json
from datetime import datetime

# 单点导航请求
def build_navigation_request(pos_x, pos_y, pos_z=0.0, angle_yaw=0.0, gait=0x3002, speed=1, nav_mode=0):
    return {
        "PatrolDevice": {
            "Type": 1003,
            "Command": 1,
            "Time": datetime.now().strftime("%Y-%m-%d %H:%M:%S"),
            "Items": {
                "Value": 0,
                "MapID": 0,
                "PosX": pos_x,
                "PosY": pos_y,
                "PosZ": pos_z,
                "AngleYaw": angle_yaw,
                "PointInfo": 1,  # 任务点
                "Gait": gait,    # 平地敏捷模式
                "Speed": speed,  # 低速
                "Manner": 0,     # 前进行走
                "ObsMode": 0,    # 开启停避障
                "NavMode": nav_mode  # 0=直线, 1=自主
            }
        }
    }

# 取消导航请求
def build_cancel_request():
    return {
        "PatrolDevice": {
            "Type": 1004,
            "Command": 1,
            "Time": datetime.now().strftime("%Y-%m-%d %H:%M:%S"),
            "Items": {}
        }
    }

# 查询导航状态请求
def build_status_query():
    return {
        "PatrolDevice": {
            "Type": 1007,
            "Command": 1,
            "Time": datetime.now().strftime("%Y-%m-%d %H:%M:%S"),
            "Items": {}
        }
    }
```
