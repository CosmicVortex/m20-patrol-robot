## 1. 协议总则

### 1.1 协议概述

本协议基于 TCP 或 UDP 协议（根据具体开发需要进行选择），适用于机器人本体与上位机（外部板卡或系统）通信使用。

### 1.2 接入通道

本协议使用时，机器人本体为 TCP/UDP 服务端，外部板卡或系统为 TCP/UDP 客户端。

| 协议 | 地址 | 端口 | 长连接 | 推荐场景 |
|---|---|---|---|---|
| UDP | 10.21.31.103 | 30000 | 否 | 高频速度指令（≥20Hz）、低延迟优先 |
| TCP | 10.21.31.103 | 30001 | 是 | 任务下发、状态订阅、可靠传输 |

### 1.3 交互机制

本协议主要使用请求/响应机制。上位机可主动向机器人本体发起数据或状态查询请求，机器人本体通过响应回复部分请求。

### 1.4 应用协议数据单元（APDU）

本协议 APDU 采用"协议头部+ASDU（应用服务数据单元）"结构，每个 APDU 可以携带 1 个 ASDU。

### 1.5 协议头部结构

协议头部长度固定 **16 字节**：

| 序号 | 内容 | 长度 | 值 | 备注 |
|---|---|---|---|---|
| 1 | 同步字符 | 1 | 0xeb | 固定 |
| 2 | 同步字符 | 1 | 0x91 | 固定 |
| 3 | 同步字符 | 1 | 0xeb | 固定 |
| 4 | 同步字符 | 1 | 0x90 | 固定 |
| 5 | 长度 | 2 | - | ASDU 字节段长度，小端字节序，最大 65535 字节 |
| 6 | 报文 ID | 2 | - | 每帧报文唯一标识，请求方控制，响应帧复用相同值，小端字节序 |
| 7 | ASDU 格式 | 1 | 0x00=XML, 0x01=JSON | ASDU 数据格式类型判断位 |
| 8 | 预留 | 7 | 0x00 | 预留 7 字节，暂填 0 |

```
┌─────────────────────────────────────────────────────────────────────┐
│                    协议头部 (16 字节)                                │
├──────┬──────┬──────┬──────┬──────┬──────┬──────┬───────────────────┤
│ 同步 │ 同步 │ 同步 │ 同步 │ 长度 │ 报文ID│ 格式 │      预留         │
│ 0xeb │ 0x91 │ 0xeb │ 0x90 │(2B)  │(2B)  │(1B)  │    (7B, 0x00)     │
└──────┴──────┴──────┴──────┴──────┴──────┴──────┴───────────────────┘
         │
         ▼
┌─────────────────────────────────────────────────────────────────────┐
│                        ASDU (N 字节)                                 │
│                    (JSON 或 XML 格式)                                │
└─────────────────────────────────────────────────────────────────────┘
```

**推荐使用 JSON 格式**，JSON 格式下 ASDU 处理性能更快且数据结构更全面，支持更多消息类型。XML 仅在与既有系统对接、或客户内部要求时使用。

### 1.6 ASDU 结构

ASDU 数据内容采用 JSON 或 XML 格式组织，包含以下通用字段：

| 字段 | 含义 |
|---|---|
| Type | 消息类型 |
| Command | 消息命令码 |
| Time | 报文发送时间，本地时区，格式：YYYY-MM-DD HH:MM:SS |
| Items | 消息所携带的参数项 |

#### JSON 示例

```json
{
  "PatrolDevice": {
    "Type": 1002,
    "Command": 1,
    "Time": "2023-01-01 00:00:00",
    "Items": {}
  }
}
```

#### XML 示例

```xml
<?xml version="1.0" encoding="UTF-8"?>
<PatrolDevice>
  <Type>1002</Type>
  <Command>1</Command>
  <Time>2023-01-01 00:00:00</Time>
  <Items/>
</PatrolDevice>
```

## 2. 接口字典

| Type | 对应子模块 | 典型 Command |
|---|---|---|
| **2** | 运动控制 | 21=运动控制轴指令, 22=运动状态, 23=步态切换, 24=自主充电 |
| **100** | 连接状态保活 | 100=心跳指令(1Hz) |
| **1002** | 机器人状态（机器人主动上报） | 3=错误列表(2Hz), 4=运动状态(10Hz), 5=系统状态(2Hz), 6=基础状态(2Hz) |
| **1003** | 导航任务 | 1=单点导航, 2=路径导航, 3=取消任务, 4=任务状态查询 |
| **1004** | 取消导航任务 | 1=取消导航任务 |
| **1007** | 导航状态查询 | 1=任务状态查询, 2=位置查询 |
| **1101** | 设备使能 | 2=照明灯, 5=模式切换, 6=休眠设置, 7=休眠配置查询 |
| **2002** | 导航感知状态 | 1=获取导航中的感知软件状态信息 |
| **2101** | 定位初始化 | 1=初始化和重置定位 |

> **文档中出现的所有 Type / Command 均为十进制数字。**

## 3. 心跳与连接保活

### 3.1 心跳机制

无论使用 UDP 或 TCP，客户端均应以不低于 **1Hz** 的频率发送任意指令作为心跳（建议使用特定的心跳指令 Type=100, Command=100）；服务端超过 **2s** 未收到客户端任何请求则认为客户端离线，停止向该客户端推送所有主动上报数据。

使用 UDP 下发运动控制轴指令或速度指令时，建议发送频率不低于 **20Hz**；服务端检测到客户端断开时会自动停止该客户端的速度指令转发，机器人进入安全状态。

建议客户端超过 **3 秒** 未收到服务端任何响应消息时判定服务端断连。

### 3.2 主动上报与心跳来源

basic_server 以心跳来源的 IP/端口作为目标地址，向客户端主动推送以下数据：

| Type | Command | 周期 | 内容 |
|---|---|---|---|
| 1002 | 3 | 2Hz / 异常事件即时上报一次 | 异常状态 |
| 1002 | 4 | 10Hz | 运控状态：姿态、速度、16 关节 |
| 1002 | 5 | 2Hz | 设备状态：电池、温度、设备、GPS |
| 1002 | 6 | 2Hz | 基础状态：运动状态、充电状态等 |

#### 订阅方式

| 协议 | 订阅方式 |
|---|---|
| TCP | 建立连接后自动接收上述所有主动上报 |
| UDP | 需先发送一次对应查询请求（如 Type=1002, Command=5），服务端记录来源 IP/端口后持续推送该类型数据 |

## 4. 通讯错误码机制

basic_server 在收到客户端下发的每一个请求后，都会返回该条消息。

### 4.1 响应格式

**JSON 形式：**
```json
{
  "PatrolDevice": {
    "Type": XXXX,
    "Command": XX,
    "Time": "2023-01-01 00:00:00",
    "Items": {
      "ErrorCode": 0,
      "ErrorMessage": "Success"
    }
  }
}
```

**XML 形式：**
```xml
<?xml version="1.0" encoding="UTF-8"?>
<PatrolDevice>
    <Type>XXXX</Type>
    <Command>XX</Command>
    <Time>2023-01-01 00:00:00</Time>
    <Items>
        <ErrorCode>0</ErrorCode>
        <ErrorMessage>Success</ErrorMessage>
    </Items>
</PatrolDevice>
```

其中，回复的 Type 和 Command 字段值与客户端下发的对应请求消息中的 Type 和 Command 字段值相同。

### 4.2 通用错误码表

| ErrorCode (十六进制) | ErrorCode (十进制) | ErrorMessage | 含义/建议动作 |
|---|---|---|---|
| 0x0000 | 0 | Success | 发送成功，可继续下一步 |
| 0xE001 | 57345 | Unsupported data format | 发送的数据格式不支持（非xml和json），建议检查帧头 Format 字段 |
| 0xE002 | 57346 | Data parsing failed | 协议格式异常，数据解析失败，缺少PatrolDevice、Items、Type、Command，建议校验 JSON/XML 格式 |
| 0xE003 | 57347 | Unsupported protocol type | 找不到Type、Command对应的协议，建议检查 Type、Command 值 |
| 0xE004 | 57348 | Missing necessary fields | 缺少协议字段 |
| 0xE005 | 57349 | Mismatched data type | 字段类型不匹配，建议校对字段类型 |
| 0xE006 | 57350 | Mismatched request client | 请求客户端不匹配，例如：轴指令发送时，要求2s内发送的指令来自同一个客户端 |
| 0xE007 | 57351 | No operation permission | 无操作权限 |
| 0xE008 | 57352 | Not allowed operation | 当前状态下不允许的操作，建议检查状态机（如未站立不能发速度） |
| 0xE009 | 57353 | Operation failure | 操作失败，建议查看 Type=1002, Cmd=3 错误详情 |
| 0xE00A | 57354 | Unsupported function | 不支持的功能，例如：导航功能只有Pro版本支持，建议确认固件版本 |
| 0xE00B | 57355 | Internal error | 内部错误，如内部文件打开失败，内部文件解析失败等，建议查看日志 |

> **注意：** ErrorCode=0x0000 仅表示命令已被接收并触发，不代表业务执行成功。
