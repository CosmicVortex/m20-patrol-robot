## 1. 本体监控协议

本协议基于TCP或UDP协议，适用于机器人本体与上位机通信使用。

### 1.1 协议总则

#### 1.1.1 协议层次

| 层级 | 说明 |
|---|---|
| 应用层（第7层） | 本协议 |
| 传输层（第4层） | TCP/IP协议或UDP/IP协议 |
| 网络层（第3层） | IP |
| 链路层（第2层） | 以太网 |
| 物理层（第1层） | - |

注：第5，第6层未用

#### 1.1.2 协议端口号

机器人本体为 TCP/UDP 服务端，外部板卡或系统为 TCP/UDP 客户端。

- UDP 服务端地址与端口：`10.21.31.103:30000`
- TCP 服务端：`10.21.31.103:30001`

#### 1.1.3 交互机制

本协议主要使用请求/响应机制。上位机可主动向机器人本体发起数据或状态查询请求，机器人本体通过响应回复部分请求。

#### 1.1.4 应用协议数据单元（APDU）

本协议 APDU 采用"协议头部+ASDU（应用服务数据单元）"结构，每个APDU可以携带1个ASDU。

#### 1.1.5 协议头部结构

协议头部长度固定16字节：

| 序号 | 内容 | 长度 | 值 | 备注 |
|---|---|---|---|---|
| 1 | 同步字符 | 1 | 0xeb | 固定 |
| 2 | 同步字符 | 1 | 0x91 | 固定 |
| 3 | 同步字符 | 1 | 0xeb | 固定 |
| 4 | 同步字符 | 1 | 0x90 | 固定 |
| 5 | 长度 | 2 | - | ASDU字节段长度，小端字节序，最大65535字节 |
| 6 | 报文ID | 2 | - | 每帧报文唯一标识，请求方控制，响应帧复用相同值，小端字节序 |
| 7 | ASDU格式 | 1 | 0x00=XML, 0x01=JSON | ASDU数据格式类型判断位 |
| 8 | 预留 | 7 | 0x00 | 预留7字节，暂填0 |

#### 1.1.6 ASDU结构

ASDU数据内容采用JSON或XML格式组织，包含以下通用字段：

| 字段 | 含义 |
|---|---|
| Type | 消息类型 |
| Command | 消息命令码 |
| Time | 报文发送时间，本地时区，格式：YYYY-MM-DD HH:MM:SS |
| Items | 消息所携带的参数项 |

【注意】推荐使用JSON格式，JSON格式下ASDU处理性能更快且数据结构更全面。

JSON示例：
```json
{
  "PatrolDevice": {
    "Type": 1002,
    "Command": 1,
    "Time": "2023-01-01 00:00:00",
    "Items": {}
  }
}
```

XML示例：
```xml
<?xml version="1.0" encoding="UTF-8"?>
<PatrolDevice>
  <Type>1002</Type>
  <Command>1</Command>
  <Time>2023-01-01 00:00:00</Time>
  <Items/>
</PatrolDevice>
```

### 1.2 控制类ASDU消息集

#### 1.2.1 心跳指令

| Type | Command | 消息类型 |
|---|---|---|
| 100 | 100 | 心跳指令 |

【注意】建议以不小于1Hz的频率发送，机器人会向持续发送心跳指令的IP和端口上报实时状态信息和异常状态信息。

JSON格式请求：
```json
{
  "PatrolDevice": {
    "Type": 100,
    "Command": 100,
    "Time": "2023-01-01 00:00:00",
    "Items": {}
  }
}
```

#### 1.2.2 使用模式切换

| Type | Command | 消息类型 |
|---|---|---|
| 1101 | 5 | 使用模式切换 |

参数项：

| 参数项 | 含义 | 数据类型 | 参数值说明 |
|---|---|---|---|
| Mode | 机器人使用模式 | int | 常规模式=0, 导航模式=1, 辅助模式=2 |

【注意】常规模式下支持执行轴指令，导航模式下支持执行导航任务。

#### 1.2.3 运动状态转换

| Type | Command | 消息类型 |
|---|---|---|
| 2 | 22 | 运动状态转换 |

参数项：

| 参数项 | 含义 | 数据类型 | 参数值说明 |
|---|---|---|---|
| MotionParam | 机器人运动状态 | int | 空闲=0, 站立=1, 关节阻尼/软急停=2, 开机阻尼=3, 趴下=4, RL控制=17 |

【注意】敏捷运动模式下的步态速度响应性能较好，适用于导航等自主算法开发。

#### 1.2.4 步态切换

| Type | Command | 消息类型 |
|---|---|---|
| 2 | 23 | 步态切换 |

参数项：

| 参数项 | 含义 | 数据类型 | 参数值说明 |
|---|---|---|---|
| GaitParam | 机器人运动步态 | int | 基础(标准)=0x1001, 高台(标准)=0x1002, 平地(敏捷)=0x3002, 楼梯(敏捷)=0x3003 |

【注意】不同运动模式下支持不同的步态，步态切换时会自动切换到对应的运动模式。

#### 1.2.5 运动控制（轴指令）

| Type | Command | 消息类型 |
|---|---|---|
| 2 | 21 | 运动控制 |

【注意】该指令仅支持在常规模式下执行。

参数项：

| 参数项 | 含义 | 数据类型 | 范围 |
|---|---|---|---|
| X | 前后方向运动速度 | float | [-1, 1] |
| Y | 左右方向运动速度 | float | [-1, 1] |
| Z | 高度方向运动速度 | float | [-1, 1] |
| Roll | 翻滚角速度 | float | [-1, 1] |
| Pitch | 俯仰角速度 | float | [-1, 1] |
| Yaw | 偏航角速度 | float | [-1, 1] |

【注意】建议控制机器人平移或旋转的请求消息发送频率为20Hz。基础或楼梯步态仅有参数项X、Y、Yaw生效。

#### 1.2.6 照明灯

| Type | Command | 消息类型 |
|---|---|---|
| 1101 | 2 | 照明灯 |

参数项：

| 参数项 | 含义 | 参数值说明 |
|---|---|---|
| Front | 前侧照明灯 | 关闭=0, 开启=1 |
| Back | 后侧照明灯 | 关闭=0, 开启=1 |

#### 1.2.7 自主充电

| Type | Command | 消息类型 |
|---|---|---|
| 2 | 24 | 自主充电 |

参数项：

| 参数项 | 含义 | 参数值说明 |
|---|---|---|
| Charge | 机器人充电状态 | 结束充电=0, 开始充电=1, 清除充电状态=2 |

【注意】下发参数项 Charge 对应参数值 2（清除充电状态，恢复为空闲状态）的指令后，机器人将强制切断充电电流、强制状态归零、同时清除相关错误记录。该操作具有风险，请谨慎使用。

#### 1.2.8 休眠模式设置

| Type | Command | 消息类型 |
|---|---|---|
| 1101 | 6 | 休眠模式设置 |

参数项：

| 参数项 | 含义 | 数据类型 | 参数值说明 |
|---|---|---|---|
| Sleep | 休眠模式启停 | bool | 进入休眠=true, 唤醒=false |
| Auto | 自动休眠开关 | bool | 是=true, 否=false |
| Time | 休眠等待时间 | int | [5, 30] 分钟 |

| Sleep | 休眠状态 | 未休眠=0, 已休眠=1, 进入休眠中=2 |

### 附录1 UDP示例代码

```c
#include <iostream>
#include <cstring>
#include <sys/socket.h>
#include <arpa/inet.h>
#include <unistd.h>

#define SERVER_IP "10.21.31.103"
#define PORT 30000
#define BUFFER_SIZE 1024

struct udpMessage {
    unsigned char header[16];
    unsigned char data[BUFFER_SIZE];
};

int main() {
    int client_fd = socket(AF_INET, SOCK_DGRAM, 0);
    
    struct sockaddr_in server_addr;
    server_addr.sin_family = AF_INET;
    server_addr.sin_port = htons(PORT);
    inet_pton(AF_INET, SERVER_IP, &server_addr.sin_addr);
    
    udpMessage message;
    message.header[0] = 0xeb;
    message.header[1] = 0x91;
    message.header[2] = 0xeb;
    message.header[3] = 0x90;
    
    const char *data = "{\"PatrolDevice\":{\"Type\":100,\"Command\":100,\"Time\":\"2023-01-01 00:00:00\",\"Items\":{}}}";
    unsigned short dataLength = strlen(data);
    
    message.header[4] = dataLength & 0xFF;
    message.header[5] = (dataLength >> 8) & 0xFF;
    message.header[6] = 0x01;
    message.header[7] = 0x00;
    message.header[8] = 0x01;
    
    memcpy(message.data, data, strlen(data));
    
    sendto(client_fd, &message, dataLength + 16, 0, (struct sockaddr *)&server_addr, sizeof(server_addr));
    
    close(client_fd);
    return 0;
}
```
