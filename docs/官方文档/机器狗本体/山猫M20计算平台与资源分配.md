## 2. 计算资源分配

> **重要：** 用户自定义节点应优先部署在 **GOS (104)** 上，NOS（106）次之，应尽量避免抢占 NOS/AOS 核心进程资源。

### 2.1 CPU 大小核架构

RK3588 采用 ARM big.LITTLE 架构，共 8 个核心：

| 核心编号 | 类型 | 架构 | 最高频率 | 特点 |
|---|---|---|---|---|
| CPU 0 ~ 3 | 小核（LITTLE） | Cortex-A55 | ~1.8GHz | 低功耗，适合后台/轻量任务 |
| CPU 4 ~ 7 | 大核（big） | Cortex-A76 | ~2.2GHz | 高性能，适合计算密集型任务 |

### 2.2 二开程序绑核建议

> **注意：** RK3588 的小核（0-3）性能偏低，资源紧张，且 CPU0 被大量用于处理硬件中断和系统中断。如果开发者的二次开发程序运行在机器人内部任一主机上，建议优先绑定到大核（CPU 4-7）上运行，以获得更好的计算性能，也避免与核心进程竞争小核资源。

```bash
# 使用 taskset 将程序绑定到大核（core 4-7）
taskset -c 4-7 ./your_program

# 示例：绑定 Python 脚本到大核
taskset -c 4-7 python3 your_node.py

# 示例：绑定 ROS2 节点到大核
taskset -c 4-7 ros2 run your_package your_node
```

### 2.3 查看核心使用情况

```bash
# 查看各核心实时使用率
htop          # 按 F2 设置 → Display options → 显示核心编号
mpstat -P ALL 1  # 每秒刷新各核心使用率

# 查看进程当前绑定的核心
taskset -cp <PID>

# 查看 CPU 核心在线状态
cat /sys/devices/system/cpu/online
```

### 2.4 各主机资源配额

| 主机 | 建议 CPU 核心 | 可用内存 | 说明 |
|---|---|---|---|
| AOS (103) | 大核 4-7 | ~12GB | 扣除系统后约 12GB 可用 |
| NOS (106) | 大核 4-7 | ~10GB | 扣除系统后约 10GB 可用 |
| GOS (104) | 大核 4-7 | ~16GB | 大部分可供二开使用 |

## 3. 部署建议

### 3.1 优先部署顺序

1. **GOS (10.21.31.104)** — 首选，资源最充裕
2. **NOS (10.21.31.106)** — 次选，注意避开导航核心进程
3. **AOS (10.21.31.103)** — 最后考虑，避免影响运动控制实时性

### 3.2 绑核示例脚本

```bash
#!/bin/bash
# 启动绑核二开程序示例

PROGRAM="./your_node"
CORES="4-7"

# 绑核启动
taskset -c $CORES $PROGRAM &
PID=$!

echo "Started $PROGRAM on cores $CORES (PID: $PID)"

# 验证绑核
taskset -cp $PID
```

### 3.3 资源监控

```bash
# 监控系统资源使用
while true; do
  echo "=== $(date) ==="
  echo "CPU 使用率:"
  mpstat -P ALL 1 1 | grep -E "CPU|all"
  echo "内存使用:"
  free -h
  echo "绑定核心:"
  for pid in $(pgrep -f your_node); do
    echo "  PID $pid: $(taskset -cp $pid | tail -1)"
  done
  sleep 5
done
```

## 4. 性能参考

### 4.1 RK3588 理论算力

| 指标 | 数值 |
|---|---|
| CPU | 8 核 ARM (4×A55 + 4×A76) |
| NPU | 6 TOPS（可选） |
| 内存带宽 | 约 68 GB/s |

### 4.2 典型负载参考

| 任务 | 推荐主机 | 预计 CPU 占用 | 预计内存占用 |

| basic_server 通信 | GOS | <5% | ~50MB |
