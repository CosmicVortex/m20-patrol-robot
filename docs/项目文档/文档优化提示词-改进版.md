# M20 Pro 项目文档优化提示词（改进版）

**版本**: 1.0  
**创建时间**: 2026-08-12  
**适用场景**: 开源项目文档体系重构

---

## 原提示词问题

```markdown
注意对仓库内文档进行一次全面优化，参照行业内优秀开源GitHub 项目的风格和结构，
重新对文档进行一次内容检查，与代码和官方资料对齐，所有内容均为真实可靠，
不要包含安全策略等无关内容。理清项目结构，是否对项目必要信息全部描述清楚。
```

**问题分析：**
1. 目标不明确 - "全面优化"范围太广
2. 缺少执行约束 - 未说明输出格式、优先级
3. 缺少验证机制 - "与代码对齐"如何验证？
4. 边界条件模糊 - "不要安全策略"过于绝对
5. 缺少验收标准 - 如何判断优化完成？

---

## 改进版提示词

```markdown
## 文档全面优化任务

### 任务目标
对[项目名称]项目仓库进行文档体系重构，参照Linux内核、ROS、home-assistant等行业优秀开源项目的文档标准，建立清晰、完整、可维护的文档结构。

### 执行步骤

#### 1. 文档结构审计
- [ ] 统计所有.md文档数量及位置
- [ ] 分析现有文档层级关系
- [ ] 识别重复、过时、缺失的文档
- [ ] 检查文档之间的引用关系

#### 2. 内容对齐验证
- [ ] 检查README.md是否包含：
  - [ ] 项目简介（功能、定位、目标用户）
  - [ ] 快速开始（3分钟内可运行）
  - [ ] 环境要求（Python版本、依赖、硬件要求）
  - [ ] 部署步骤（一键部署命令）
  - [ ] 目录结构说明
  - [ ] 故障排查指南
- [ ] 验证代码注释与文档描述是否一致
- [ ] 对照官方手册核对技术术语
- [ ] 确认所有API端点在文档中有对应说明

#### 3. 文档优化执行
- [ ] 精简冗余描述，删除过程性内容（如诊断记录、临时方案）
- [ ] 补充缺失的必要信息（环境要求、配置项说明、故障排查）
- [ ] 统一命名规范（中文文档使用规范命名，避免口语化）
- [ ] 修复断裂链接
- [ ] 添加必要的图表说明（架构图、流程图、数据流图）

#### 4. 质量控制
- [ ] 所有技术描述必须有代码或官方文档依据
- [ ] 删除主观判断、推测性内容
- [ ] 确保部署命令可执行、配置项可验证
- [ ] 保留必要的警示信息（如安全注意事项、版本兼容性）

### 输出要求
1. 生成《文档优化报告.md》，包含：
   - 优化前后对比
   - 发现的问题清单
   - 修改记录（文件路径、修改内容、修改原因）
2. 直接修改源文档，保持原有目录结构
3. 不创建临时文件或备份

### 参考标准
- home-assistant：配置文档结构、设备集成说明
- ROS：节点通信文档、API参考格式
- linux.kernel：技术文档严谨性、版本号管理
- echarts：前端项目文档组织方式

### 验收标准
- [ ] README.md包含所有必要章节（8个以上）
- [ ] 所有技术描述有代码或文档依据
- [ ] 部署命令可执行
- [ ] 无断裂链接
- [ ] 术语使用一致
- [ ] 无TODO/FIXME标记
```

## 改进要点总结

| 维度 | 原提示词 | 改进后 |
|------|----------|--------|
| **结构** | 一段式描述 | 四阶段流程（审计→验证→优化→质控） |
| **验证** | 无标准 | 30+项检查清单 |
| **参考** | 无具体项目 | 指定4个参考项目 |
| **输出** | 不明确 | 报告+源文档修改+不创建临时文件 |
| **边界** | "不要安全策略" | "保留必要警示" |
| **验收** | 无标准 | 6项验收清单 |
