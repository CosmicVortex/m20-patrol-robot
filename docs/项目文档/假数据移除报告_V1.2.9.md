# 假数据移除报告 V1.2.9

**日期**: 2026-08-14
**Git提交**: current HEAD
**问题**: 电池显示92%和88%是硬编码假数据

---

## 问题诊断

### 原始代码位置
`backend/app/robot/telemetry.py:311-320` (模拟模式)
`backend/app/robot/telemetry.py:428-437` (fallback模式)

```python
# ❌ 错误的硬编码假数据
self._snapshot.device = {
    "battery_list": [
        {"BatteryLevel": 92, "Voltage": 25.5, "serial": "B001"},
        {"BatteryLevel": 88, "Voltage": 25.2, "serial": "B002"}
    ],
    "battery_status": {
        "BatteryLevelLeft": 92,
        "BatteryLevelRight": 88,
        ...
    }
}
```

### 触发条件
当 `connected=False` 且 `basic` 为空时，调用 `_generate_fallback_data()` 生成假数据。

---

## 修复方案

### 1. 移除假数据生成方法
删除 `_generate_fallback_data()` 方法，不再有任何假数据生成逻辑。

### 2. 修改快照更新逻辑
```python
# ✅ 正确：保持空状态，不生成假数据
def _update_snapshot_no_client(self, *, error: str) -> None:
    # ...
    self._snapshot.error_message = error or "通信异常：无法连接到AOS basic_server"
    
    # 只重置为安全默认值，不填充假数据
    if not self._snapshot.basic:
        self._snapshot.basic = {}
    if not self._snapshot.device:
        self._snapshot.device = {}
    # ... 其他字段同理
```

### 3. 前端状态显示
前端已正确处理空数据：
- `battery == null` → 显示 "暂无数据"
- `battery_left/right == null` → 显示 "-"
- `connected == false` → 显示 "NO DATA / WAITING"

## 数据流验证

### 有真实数据时
```
AOS TCP连接成功
    ↓
_parse_status_message() 解析真实协议数据
    ↓
_snapshot.device.battery_list = [{"BatteryLevel": 85, ...}]
    ↓
_resolve_battery() 返回真实电量
    ↓
前端显示真实值
```

### 无真实数据时
```
连接失败或超时
    ↓
_update_snapshot_no_client() 被调用
    ↓
source = "NO_DATA"
device = {} (空字典)
    ↓
_resolve_battery() 返回 0
    ↓
前端显示 "暂无数据" 或 "-"
```
