## 症状分类

### 1. Web UI显示"NO_DATA / WAITING"

**原因**: TCP连接未建立或心跳未发送

**排查步骤**:

```bash
# 1. 检查服务状态
systemctl --user status m20-patrol-readonly.service

# 2. 查看日志
journalctl --user -u m20-patrol-readonly.service -n 50 --no-pager -l | grep -E "连接|遥测|ERROR"

# 3. 测试AOS连通性
ping -c 3 10.21.31.103
timeout 5 bash -c 'echo | nc -v 10.21.31.103 30001'

# 4. 检查心跳配置
grep telemetry_tx_enabled deploy/readonly-manifest.json
```

**常见原因及修复**:

| 现象 | 原因 | 修复 |
|------|------|------|
| TCP超时 | AOS关机/网线断开 | 检查物理连接 |
|| 连接被拒绝 | AOS服务未启动 | 检查AOS服务状态 |
| 心跳禁用 | 配置错误 | 修改manifest.json为true |
| IP变更 | DHCP重新分配 | 更新manifest中的aos_host |

---

### 2. 健康检查返回healthy=false

**排查命令**:

```bash
curl -s http://127.0.0.1:8080/api/v1/health | python3 -m json.tool
```

**关键字段含义**:

| 字段 | 期望值 | 问题定位 |
|------|--------|----------|
| `source` | `REAL` | NO_DATA=无连接, ERROR=解析失败, STALE=超时 |
| `connected` | `true` | false=TCP断开 |
| `valid_frames` | >0 | 0=无有效帧 |
| `bytes_received` | >0 | 0=无数据 |
| `telemetry_fresh` | `true` | false=数据超时(>3秒) |
| `age_ms` | <3000 | >3000=数据过时 |

---

### 3. 数据解析错误 (source=ERROR)

**排查步骤**:

```bash
# 查看详细错误
journalctl --user -u m20-patrol-readonly.service -n 100 --no-pager -l | grep "Parse error"

# 测试协议解析
python3 -c "
import sys; sys.path.insert(0, '.')
from backend.app.protocol.frame import FrameCodec, m20_v010_layout
from backend.app.protocol.messages import decode_patrol_message, ASDUFormat
# 手动测试解析
"
```

**可能原因**:
- APDU帧格式不匹配（固件版本差异）
- 网络传输层问题导致帧截断
- 编码问题（UTF-8 vs ASCII）

---

### 4. 视频流无法播放

**排查命令**:

```bash
# 检查FFmpeg
ffmpeg -version | head -1
command -v ffprobe

# 测试RTSP拉流
ffplay -rtsp_transport tcp -i rtsp://10.21.31.103:8554/av0_0

# 检查端口
netstat -tlnp | grep 8554
```

**常见问题**:
- FFmpeg版本<7.1，不支持RTSP over TCP
- 网络带宽不足（需≥4Mbps）
- RTSP路径错误（需确认具体通道编号）

---

### 5. 运动控制无响应

**前置条件**:
- 运动控制已授权: `curl -X POST http://127.0.0.1:8080/api/v1/motion/authorize`
- 不在只读模式: `grep read_only_mode deploy/readonly-manifest.json`

**排查命令**:

```bash
# 检查授权状态
curl -s http://127.0.0.1:8080/api/v1/navigation/status | python3 -m json.tool

# 测试控制指令
curl -X POST http://127.0.0.1:8080/api/v1/motion/axis -H "Content-Type: application/json" -d '{"x":0.5,"y":0,"yaw":0}'
```

## 日志分析指南

### 关键日志条目

| 日志关键词 | 含义 | 处理方式 |
|------------|------|----------|
| `连接到...成功` | TCP连接建立 | 正常 |
| `遥测异常` | 数据处理错误 | 检查协议版本 |
| `Parse error` | 帧解析失败 | 检查网络质量 |
| `心跳已发送` | 心跳正常 | 正常 |
| `RECONNECTING` | 正在重连 | 等待恢复 |

### 日志文件位置

```
journalctl --user -u m20-patrol-readonly.service -f  # 实时日志
~/.config/systemd/user/m20-patrol-readonly.service  # 服务配置
~/m20-patrol-robot/deploy/readonly-manifest.json   # 部署配置
```

## 紧急处理

### 服务完全无响应

```bash
# 1. 强制停止
systemctl --user stop m20-patrol-readonly.service

# 2. 清理旧进程
pkill -f "m20-patrol-robot" || true

# 3. 重新启动
systemctl --user start m20-patrol-readonly.service

# 4. 验证
sleep 3 && curl -s http://127.0.0.1:8080/api/v1/health
```

### 配置错误导致无法启动

```bash
# 恢复默认配置
cp deploy/readonly-manifest.json.deploy-example deploy/readonly-manifest.json

# 重新部署
bash deploy/scripts/deploy-readonly.sh --one-shot
```
