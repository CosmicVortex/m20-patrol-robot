**版本**: V1.1

**依据**: 《山猫M20软件开发指南V1.2.1》《basic_server通信协议总览V1.0.0》

## 1. 系统概述

M20 Pro巡逻机器人系统是面向中升之星奔驰4S店的安保巡逻系统。系统采用边缘计算架构，部署在GOS（Guard Operator Station）边缘主机上，通过basic_server协议与M20 Pro AOS通信，实现状态监控、视频回传、运动控制、导航管理等功能。

## 4. 通信协议栈

```
┌─────────────────────────────────────────────────────────────┐
│ 应用层                                                        │
│  ├── REST API (HTTP/JSON)                                    │
│  ├── WebSocket (实时推送)                                    │
│  └── basic_server 协议 (Type/Command 消息)                    │
├─────────────────────────────────────────────────────────────┤
│ 传输层                                                        │
│  ├── TCP 30001 (基本控制 + 状态订阅)                          │
│  ├── UDP 30000 (高频指令)                                    │
│  └── RTSP 8554 (视频流)                                      │
├─────────────────────────────────────────────────────────────┤
│ 网络层                                                        │
│  └── 10.21.31.0/24 (现场局域网)                               │
└─────────────────────────────────────────────────────────────┘
```

### 4.1 basic_server 协议格式

APDU头部结构（16字节固定）:
- 同步字符: `0xEB 0x91 0xEB 0x90`
- 长度: 小端2字节，ASDU字节数（不含头部）
- 报文ID: 小端2字节，请求响应匹配
- 格式: 0=XML, 1=JSON
- 预留: 7字节，填0

> **注意**: Type和Command字段位于ASDU载荷（JSON）中，不在APDU头部。

### 4.2 心跳机制

| 参数 | 值 | 说明 |
|------|-----|------|
| 心跳间隔 | 1.0s | ≥1Hz符合要求 |
| 心跳类型 | Type=100, Cmd=100 | 任意指令即可 |
| 超时判定 | >2s无心跳 | AOS停止推送 |
| 断线重连 | 自动 | 1秒间隔重试 |

## 7. 数据流向

### 7.1 状态订阅流（数据上行）

```
AOS (10.21.31.103:30001)
    │ Type=1002/1007 主动推送
    ▼
BasicServerClient.receive_messages()
    │ TCP接收
    ▼
FrameCodec.decode() → IncrementalDecoder.feed()
    │ APDU帧解析
    ▼
decode_patrol_message() → PatrolMessage
    │ ASDU解析
    ▼
parse_status_message() → StatusResult
    │ 状态归类
    ▼
TelemetryAdapter._process_message()
    │ 更新快照
    ▼
TelemetryAdapter.get_status_payload()
    │ API响应
    ▼
GET /api/v1/status/latest
    │ HTTP响应
    ▼
Browser (前端轮询/WebSocket)
```

### 7.2 控制指令流（数据下行）

```
Web Browser
    │ POST /api/v1/motion/axis
    ▼
AxisControlHandler
    │ 检查 read_only_mode + auth + admin
    ▼
MotionControlService
    │ 检查安全快照（运动状态、电量、急停）
    ▼
BasicServerClient.send_control()
    │ 构建APDU帧
    ▼
encode_patrol_message() → bytes
    │ TCP发送
    ▼
AOS (10.21.31.103:30001)
```

## 9. 安全架构

### 9.1 控制权限层级

| 层级 | 配置 | 权限范围 |
|------|------|----------|
| Level 1 | read_only_mode=true | 所有控制指令禁止 |
| Level 2 | control_enabled=false | Web UI控制按钮禁用 |
| Level 3 | auth_required=true + admin role | 需显式授权才能发送控制指令 |

### 9.2 安全快照检查

每次控制指令发送前检查:
- 运动状态不在软急停/摔倒
- 电量 > 20%
- 导航模块无异常
- 操作员已授权

## 10. 运动状态与步态定义

### 10.1 运动状态值

| 十进制值 | 十六进制 | 名称 | 说明 |
|----------|----------|------|------|
| 0 | 0x00 | 空闲 | 空闲状态，无动作，等待指令 |
| 1 | 0x01 | 站立 | 临时过渡状态，自动跳转到RL控制 |
| 2 | 0x02 | 软急停 | 关节断电，最高优先级，任意状态可触发 |
| 3 | 0x03 | 开机阻尼 | 开机后自动进入的阻尼状态 |
| 4 | 0x04 | 趴下 | 安全趴下状态 |
| 17 | 0x11 | RL控制 | 强化学习控制模式，唯一可执行移动和步态切换的状态 |

> **关键**: 站立（1）是临时过渡状态，机器人会自动从站立（1）进入RL控制（17）。

### 10.2 步态值

| 十六进制 | 十进制 | 名称 | 运动模式 | 适用场景 |
|----------|--------|------|----------|----------|
| 0x1001 | 4097 | 基础 | 标准 | 室内平坦地面，手动遥控 |
| 0x1003 | 4099 | 楼梯 | 标准 | 台阶/路沿，手动遥控 |
| 0x3002 | 12290 | 平地 | 敏捷 | 自主导航 + 平地行走 |
| 0x3003 | 12291 | 楼梯 | 敏捷 | 自主导航 + 台阶跨越 |

> **注意**: 敏捷模式步态速度响应性能较好，适用于导航等自主算法开发。每次起立后或切换使用模式时，步态自动重置为基础步态（0x1001）。
