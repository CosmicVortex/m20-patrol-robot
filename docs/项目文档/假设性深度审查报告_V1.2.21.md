### 场景3: AOS推送数据，但客户端未接收

**可能原因**:

#### 3.1 socket.recv超时

**代码分析**:
```python
# basic_client.py:215-236
def _receive_from_socket(self, *, timeout_seconds: float) -> List[PatrolMessage]:
    connection = self._require_socket()
    connection.settimeout(timeout_seconds)  # 设置超时
    try:
        data = connection.recv(65536)       # 阻塞等待数据
    except socket.timeout:
        return []                           # 超时返回空列表
    ...
```

**潜在问题**: 如果AOS没有持续发送数据，socket.recv会阻塞直到超时

**当前行为**: 
- 主循环中receive_messages(timeout=0.5s)等待最多0.5秒
- 如果超时，返回空列表，继续心跳发送
- 这是预期行为 ✓

#### 3.2 缓冲区溢出或内存泄漏

**代码分析**:
```python
# basic_client.py:215-236
self._inbox: Deque[PatrolMessage] = deque()  # 无限增长的队列

def receive_messages(self, *, timeout_seconds: float) -> List[PatrolMessage]:
    if self._inbox:
        messages = list(self._inbox)
        self._inbox.clear()  # 清空缓冲区
        return messages
    return self._receive_from_socket(timeout_seconds=timeout_seconds)
```

**潜在问题**: 
- 如果消息接收速度 > 处理速度，`_inbox` 可能无限增长
- 但实际场景：AOS主动推送，客户端接收后立即清空，不存在积压

**验证结果**: ✅ 无内存泄漏风险

### 场景4: 数据接收成功，但解析失败

**可能原因**:

#### 4.1 ASDU解析失败

**代码分析**:
```python
# messages.py:127-145
def decode_patrol_message(payload: bytes, asdu_format: ASDUFormat) -> PatrolMessage:
    try:
        envelope = json.loads(payload.decode("utf-8"))  # UTF-8解码
    except UnicodeDecodeError as exc:
        raise ClientStateError(f"invalid utf-8 payload: {exc}") from exc
    except json.JSONDecodeError as exc:
        raise ClientStateError(f"invalid JSON: {exc}") from exc
    
    device = envelope.get("PatrolDevice", {})
    return PatrolMessage(
        message_type=device.get("Type", 0),
        command=device.get("Command", 0),
        sent_at=device.get("Time", ""),
        items=device.get("Items", {}),
    )
```

**潜在问题**:
1. ❌ UTF-8编码错误 → AOS发送的不是UTF-8？
2. ❌ JSON格式错误 → AOS发送的不是标准JSON？
3. ❌ 字段缺失 → AOS发送的消息缺少必要字段？

**官方文档验证**:
```json
{
  "PatrolDevice": {
    "Type": 1002,
    "Command": 6,
    "Time": "2023-01-01 00:00:00",
    "Items": {
      "BasicStatus": {...}
    }
  }
}
```

**代码匹配**: ✅ 完全符合官方JSON格式

#### 4.2 帧解码失败

**代码分析**:
```python
# frame.py:127-158
def decode(self, data: bytes) -> Frame:
    if len(data) < self.layout.header_size:  # 检查头部完整性
        raise FrameProtocolError("truncated header")
    if data[:4] != self.layout.sync_word:    # 检查同步字符
        raise FrameProtocolError("invalid sync word")
    
    length_value = self._get(data, 4, 2)     # 读取长度
    payload_size = length_value - self.layout.header_size if self.layout.length_includes_header else length_value
    
    if payload_size < 0 or payload_size > self.max_payload_size:  # 检查长度范围
        raise FrameProtocolError("invalid payload length")
    
    return Frame(message_id=..., payload=data[16:], flags=...)
```

**潜在问题**: `length_includes_header=False` 假设长度字段不包含头部

**官方文档**: "ASDU字节段长度"，通常指ASDU本身长度，不包含APDU头部

**验证需求**: 需要实际抓包确认AOS发送的帧格式

## 四、最可能的失败点（按优先级排序）

### 优先级1: 心跳未发送导致AOS停止推送

**症状**:
- 日志显示"遥测连接成功"
- 但valid_frames和bytes_received不增加
- 前端显示"WAITING"或"NO DATA"

**诊断命令**:
```bash
journalctl --user -u m20-patrol-readonly -f | grep -E "心跳|遥测"
curl -s http://localhost:8080/api/v1/health | python3 -m json.tool
```

**期望输出**:
```
INFO: 心跳已发送 (非阻塞)
INFO: 已接收 10 条状态消息
INFO: 已接收 20 条状态消息
...
```

### 优先级2: TCP连接断开后未重连

**症状**:
- 服务启动时显示连接成功
- 几秒后显示"遥测数据超时，重新连接..."
- 循环重连但无法稳定连接

**诊断命令**:
```bash
journalctl --user -u m20-patrol-readonly -f | grep -E "重连|stale"
```

### 优先级3: 帧解析失败

**症状**:
- 日志显示"消息解析失败"
- valid_frames不增加，invalid_frames增加

**诊断命令**:
```bash
journalctl --user -u m20-patrol-readonly -n 200 | grep "解析失败"
```
