### 3.3 RTSP 支持分析

**关键发现**：
- FFmpeg 的 RTSP 支持通过 **rtp demuxer** + **tcp/udp protocol** 实现
- `-protocols` 输出不包含 "rtsp" 字样，但 `rtp` 协议在列表中
- `-demuxers` 输出包含 `DE rtsp`，表示 RTSP 输入支持
- 这是 FFmpeg 的正常架构：RTSP 作为应用层协议，底层使用 RTP/RTCP over TCP/UDP

**验证命令**：
```bash
$ ffmpeg -hide_banner -demuxers 2>/dev/null | grep -iE "rtsp|live_flv"
 D   rtsp            RTSP input
 D   live_flv        live RTMP FLV (Flash Video)

$ ffmpeg -hide_banner -protocols 2>/dev/null | grep -iE "rtp|rtmp|tcp|udp"
  rtsp            RTSP output
  rtp             RTP input
  rtmp            RTMP input
  rtmpt           RTMP tunnelled input
  rtmpte          RTMP TLS input
  tcp             TCP input
  udp             UDP input
  udplite         UDPLite input
```

**结论**：离线 FFmpeg 7.1 支持完整的 RTSP 功能，可用于视频流代理。

## 四、部署问题记录

### 4.1 FFmpeg RTSP 检测逻辑缺陷（已修复）

**问题描述**：部署脚本检查 `-protocols` 输出中是否包含 "rtsp"，但 FFmpeg 的 RTSP 支持通过 `rtp demuxer + tcp/udp protocol` 实现，而非独立的 "rtsp protocol"。

**根本原因**：
- FFmpeg 架构中，RTSP 是应用层协议，通过 `libavformat` 的 `rtsp` demuxer 实现
- 传输层使用 `rtp` 协议 + `tcp`/`udp` 协议
- `-protocols` 输出的是传输层协议，不包含应用层协议名称

**修复方案**：
```bash
# 原检查（错误）：
ffmpeg -hide_banner -protocols 2>/dev/null | grep -qw rtsp

# 修正后检查：
# 1. 检查 RTSP demuxer
ffmpeg -hide_banner -demuxers 2>/dev/null | grep -qw rtsp
# 2. 检查传输层支持
ffmpeg -hide_banner -protocols 2>/dev/null | grep -qwE "(^|\s)(tcp|udp)(\s|$)"
```

**提交记录**：`9062dff` — FFmpeg RTSP检测逻辑修正

**问题描述**：用户执行 `tar xzf m20-patrol-robot-offline-deploy.tar.gz -C /` 时提示权限不足。

## 八、关键技术发现

### FFmpeg RTSP 支持架构

```
RTSP 应用层协议
    ↓
rtsp demuxer (libavformat)
    ↓
RTP/RTCP 协议
    ↓
tcp/udp protocol (libavformat)
    ↓
IP 传输层
```

**验证方法**：
```bash
# 方法1：检查 demuxer
ffmpeg -hide_banner -demuxers 2>/dev/null | grep rtsp

# 方法2：检查传输协议
ffmpeg -hide_banner -protocols 2>/dev/null | grep -E "rtp|tcp|udp"

# 方法3：实际测试 RTSP 连接（需要真实 RTSP 服务器）
ffprobe rtsp://localhost:8554/test 2>&1 | head -5
```

**注意**：`-protocols` 输出中包含 `rtsp RTSP output`，表示 RTSP 推流支持，但 RTSP 拉流通过 `rtp demuxer + tcp/udp protocol` 实现。
