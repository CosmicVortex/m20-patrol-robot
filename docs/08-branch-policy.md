# 分支管理策略

## 核心原则

**main 分支 = 唯一稳定分支**，保留最新完整代码及文档。

## 分支策略

### 当前阶段（开发期）

- **main**：唯一工作分支，所有功能开发在此进行
- **tag**：功能测试通过时打 tag，如 `v0.1.0`、`v0.2.0`
- **不创建新分支**，除非功能需要长期隔离测试

### 后续阶段（功能测试通过后）

如需长期开发新特性，可创建功能分支：

```
feature/<模块>-<描述>
fix/<问题描述>
docs/<变更内容>
```

合并回 main 前必须：
1. `pytest -q` 全部通过
2. `compileall backend/` 无错误
3. 代码审查通过
4. 相关文档更新

## 版本标签

| Tag | 含义 | 创建条件 |
|-----|------|----------|
| `v0.1.0-draft` | 云端基线（当前） | 代码+文档齐全，待 GOS 部署 |
| `v0.1.0` | 首个可用版本 | GOS 部署成功，真实遥测验证通过 |
| `v0.x.x` | 功能迭代版本 | 新功能验收通过 |

## 归档策略

- 历史执行报告归档到 `docs/archive/legacy/`
- 保留归档记录，不作为当前实施依据
- 定期清理过时文档
