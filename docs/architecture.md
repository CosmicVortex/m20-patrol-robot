# 第一阶段架构

## 1. 部署边界

第一阶段业务程序部署在 M20 Pro 的 GOS。AOS 继续承担运动控制和 `basic_server`，NOS 继续承担建图、定位和导航。项目不修改 AOS/NOS 原厂服务、网络路由或地图原始文件。

```text
浏览器
  ├─ 状态与轨迹展示
  └─ 视频展示（后续接入）
          │
          ▼
GOS
  ├─ Web/API
  ├─ 状态聚合
  ├─ 视频网关
  ├─ 地图副本展示
  └─ 后续导航安全门控
      │                  │
      │ TCP 30001        │ 地图只读副本
      ▼                  ▼
AOS basic_server       NOS
```

当前代码没有 TCP 客户端、视频转码器、轨迹服务、导航门控或导航状态机。仪表盘只提供模拟状态。

## 2. 协议与状态

《软件开发指南》V1.2.1 规定 APDU 固定为 16 字节：同步字 `EB 91 EB 90`，ASDU 长度和报文 ID 均为小端 2 字节，格式位 XML=`0`、JSON=`1`，后续 7 字节为零保留区。

官方候选端口：

- UDP：`10.21.31.103:30000`
- TCP：`10.21.31.103:30001`

当前仓库仅实现离线编解码，禁止建立到上述端口的连接。真实接入前需要现场确认 AOS 主机、固件、授权、实际协议样本和状态字段。

后续状态服务需要显式携带：

```json
{
  "source": "REAL | SIMULATED",
  "connected": true,
  "received_at": "ISO-8601",
  "age_ms": 120,
  "data": {}
}
```

模拟数据不得伪装成真实设备状态。

## 3. 地图、路线和轨迹

NOS 原生维护地图，手册目录为：

```text
/var/opt/robot/data/maps
```

`active` 软链接指向当前用于定位和导航的地图。GOS 只读取经核验的地图副本用于展示，不编辑 NOS 原始地图。

第一阶段路线和点位由官方 APP 在机器人原生流程中建立和验证。自研 Web 不生成或写入机器人路线数据。

后续轨迹展示依赖经确认的地图坐标接口和坐标系核验。定位丢失后必须停止轨迹延伸。

## 4. 视频

官方资料记录前后本体相机候选源：

```text
rtsp://10.21.31.103:8554/video1
rtsp://10.21.31.103:8554/video2
```

默认资料描述为 H.265、1280×720、30 fps、单路约 1.8 Mbps。实际设备必须测试确认。

浏览器不能直接依赖 RTSP/H.265。后续在 GOS 验证共享的 WebRTC/H.264 管线；HLS/H.264 可作为延迟较高的备选。不得为每个浏览器单独创建转码进程，也不得修改 AOS 原厂推流脚本。

## 5. 控制边界

《导航任务下发》页面说明该功能仅支持 M20 Pro。单点导航会进入规划、步态和运动控制链路，不能作为普通 Web 操作直接开放。

导航功能的放行顺序：

1. 完成地图核验和备份；
2. 完成定位核验；
3. 使用官方 APP/遥控器完成隔离区域内的单点基线测试；
4. 完成真实状态、异常、定位和连接状态解析；
5. 完成导航安全门控、审计与授权；
6. 取得现场书面安全放行；
7. 单独评审 Web 是否增加受控导航入口。

当前控制默认关闭，不得通过 Web、自研 TCP 客户端或 ROS2 话题下发运动、导航、步态或定位重置指令。

## 6. 版本管理

- 协议与接口以最新《软件开发指南》文件版本为准；当前已核验版本为 V1.2.1（2026-05-18）。
- 机器人软件/固件版本必须以现场输出确认。
- V1.1.6 已变更步态等接口，旧值不能直接复用。
- V1.1.7/V1.1.8 包含 ROS2 保护、网络、导航和 APP 标点相关变化。升级须由厂商和现场负责人另行批准。
