# M20 Pro 项目架构

## 1. 当前可交付架构

```text
开发机 / GOS
  ├─ backend.app.protocol       APDU/ASDU 离线编解码
  ├─ backend.app.dashboard      回环地址模拟只读页面
  └─ deploy/scripts              只读采集、安装、回滚

现场机器人网络（当前不连接）
  ├─ AOS                       basic_server、运动控制
  └─ NOS                       建图、定位、导航
```

当前代码包含仅用于离线验证的 TCP 传输原语和 V0.1.0 导航报文构造器，但没有真实状态聚合、视频转码器、巡逻状态机或实机发送放行。GOS 部署服务仍只显示模拟状态。

地图和视频资产由 `backend/app/site_assets.py` 做证据门控：[内部测试场地] 与 [客户场地] 分别持有地图身份和整包哈希；本体前后相机可以登记但必须逐路现场验证后才可用；第三方视频源没有真实 URI 前保持不可用。

## 2. 目标架构

```text
浏览器
   │ 仅连接 GOS
   ▼
GOS
  ├─ 只读状态服务
  ├─ 地图副本与轨迹服务
  ├─ 视频网关
  └─ 经放行的导航服务
       │
       ├─ AOS basic_server：状态与任务接口
       └─ NOS：地图、定位、规划
```

目标架构只有在需求基线 R-06 至 R-09 的准入条件全部满足后才可逐项建设。目标结构不是当前实现说明。

## 3. 数据与控制边界

- AOS/NOS 原厂服务、网络路由和原始地图不由项目程序修改；
- GOS 只读取经核验的地图副本；
- 模拟状态必须标识 `SIMULATED`，不得显示为真实设备状态；
- 未经版本、权限、真实样本和安全放行确认，不建立 AOS 连接，不发送心跳或控制报文；
- 控制能力必须独立于只读服务，默认关闭并 fail-closed；
- 现场测试优先使用官方 APP/遥控器，项目程序不介入运动控制。

## 4. 版本规则

协议字段的实现依据必须写明具体文件和页码。当前 `frame.py` 的布局来自受控《山猫 M20 系列软件开发手册》V0.1.0 第 6–8 页；它尚未作为《软件开发指南》V1.2.1或当前固件的实机协议事实确认。真实接入前必须重新核对。

## 5. 一键部署目标

当前一键部署目标是 GOS 上的模拟只读基线：

1. 固定提交检出；
2. 创建独立虚拟环境；
3. 创建独立运行环境；若环境已提供 pytest，则运行离线测试；
4. 运行测试和编译检查；
5. 安装仅绑定 `127.0.0.1` 的 systemd 服务；
6. 默认 `control_enabled=false`；
7. 保存上一版本并支持回滚。

这套入口不能宣称已经部署真实导航系统。
