### 1.2 两种导航控制路径

本项目需要区分两层概念：产品手册中的“使用模式”是常规模式、导航模式、辅助模式；点位属性中的“导航模式”是直线导航或自主导航。本节所说的两种，是启动和控制导航任务的路径，不是上述产品字段的两种取值。

系统支持两种导航控制路径，但两者的验证阶段和控制边界不同：

1. **遥控器/APP 控制路径：** 在 APP 控制界面通过“使用模式”切换到“导航模式”，再用标点工具保存和执行路线；点位属性中的“导航模式”按本次路线配置为“自主导航”。本次下午测试只验证该路径。
2. **二次开发导航：** 后续由 GOS 上的二次开发程序，经 `basic_server` 下发单点导航任务并获取执行状态。V0.1.0 定义 `1003/1` 下发任务、`1004/1` 取消任务、`1007/1` 查询任务状态，`1007/2` 查询地图坐标；该方式当前不具备实机测试条件，不得在本次测试中启用。

当前仓库包含受证据门控的 `basic_server` TCP 客户端原语，以及仅用于离线测试的导航报文构造与门控模型；当前部署服务不启用真实连接、心跳、导航发送、任务状态机或 Web 控制入口。`backend/app/dashboard.py` 只返回 `SIMULATED` 状态，并强制绑定 `127.0.0.1`。本次测试不修改程序，不通过 Web 或二次开发下发任何控制报文。

## 3. 安全与停止条件

开始前确认：

- 机器人周围至少 2 m 清空；人员与机器人保持至少 2 m 安全距离；
- 两块电池已安装、状态正常；两块电池均低于 20% 时停止并充电或更换；
- 手柄已连接，软急停可用；硬急停仅用于软急停失效、冒烟、进水或其他紧急情况；
- 遥控器操作员、安全观察员和现场负责人到位；
- 测试区无玻璃、冰面、湿滑瓷砖、高处边缘、未评估坡道或人群干扰；
- 激光雷达无遮挡，建图区无频繁走动人员和大型临时物体；
- 本次路线全程可视，只做低速、前进、避障开启的单点验证。

以下任一情况立即停止：定位丢失；红色异常保护或持续黄色预警；腿乱摆、剧烈晃动、摔倒；低电量；人员进入排除区；路线偏离预期。

- 机器人异常运动：使用手柄软急停，使机器人趴下；
- 机器人摔倒且关节仍在摆动：人员先撤离并保持安全距离，等待各关节完全停止运动 30 秒后，再按硬急停；不得在关节仍摆动时立即触发硬急停；
- 正在建图：确认机器人和人员安全后，在 NOS 建图终端执行 `sudo drmap stop_mapping`，等待建图结束；
- 硬急停会使站立机器人直接下坠，正常运动中严禁作为常规停止方式。

## 5. 建图与地图备份

### 5.1 NOS 建图前核验

登录 NOS 后执行：

```bash
command -v drmap
ls -ld /var/opt/robot/data/maps
readlink -f /var/opt/robot/data/maps/active 2>&1 || true
```

`drmap` 或地图目录不存在时停止，保留完整输出，不猜测替代路径。

### 5.2 启动建图

本次地图名称：`hxzx_office_20260806_1400`。

```bash
sudo drmap mapping -n hxzx_office_20260806_1400
```

等待约 3–5 秒，确认终端显示 `Building map` 或等效提示后开始行走。路线先小回环、后大回环，覆盖门口拍照点、充电桩周边和两点之间的通行区域。避免急加速、急刹车和急转弯。

结束建图：

```bash
sudo drmap stop_mapping
```

等待终端明确显示建图结束后再关闭终端。

### 5.3 核验与整包备份

```bash
printf '===== ACTIVE MAP =====\n'
readlink -f /var/opt/robot/data/maps/active
printf '\n===== MAP FILES =====\n'
find -L /var/opt/robot/data/maps/active -maxdepth 1 -type f -printf '%f %s bytes\n' | sort
printf '\n===== OCCUPANCY METADATA =====\n'
sed -n '1,20p' /var/opt/robot/data/maps/active/occ_grid.yaml

mkdir -p /home/user/Downloads
drmap pack
ls -lah /home/user/Downloads
```

确认本次生成的 zip 文件名后：

```bash
MAP_PACKAGE_FILE='实际生成的地图包文件名.zip'
test -f "/home/user/Downloads/$MAP_PACKAGE_FILE" || { echo '地图包不存在，停止'; exit 2; }
sha256sum "/home/user/Downloads/$MAP_PACKAGE_FILE" | tee /home/user/map-backup-sha256.txt
```

地图只能整体管理。不得单独复制、替换或编辑地图包内 `pgm`、`yaml`、`pcd` 等文件。本次办公室建图不执行 `drmap unpack`；该命令仅用于经批准的整包恢复/迁移，手册说明解压并激活后需重启生效，必须另有地图包、目标场地、备份与回滚审批。

## 6. RViz 定位核验

在 NOS 图形会话中执行：

```bash
su
source /opt/ros/foxy/setup.bash
export XAUTHORITY=/home/user/.Xauthority
rviz2
exit
```

`su` 后仅执行启动 RViz 所需命令；关闭 RViz 后立即 `exit`。在 RViz 中加载：

```text
/opt/robot/share/localization/conf/localization.rviz
```

检查实时点云是否与激活地图重合。不重合时选择 **2D Pose Estimate**，在地图上点击真实位置并沿真实机头方向拖动箭头。只有点云与地图重合、定位可信后，才可进行标点和路线测试。

## 7. APP 标点工具

### 7.1 启用与路线管理

根据产品手册 V1.1.0：

1. APP 控制界面点击 **设置**；
2. 进入 **辅助功能**；
3. 找到并开启 **标点工具**；
4. 返回控制页面，点击 **标点工具**，进入路线列表。

路线列表支持：编辑/删除路线、设置单条路线循环次数、执行/停止路线、新增路线、保存路线列表。

新建或编辑路线后，可编辑/删除点位、新增点位、在选中点位前插入点位和保存路线。

### 7.2 任务点 1：门口拍照点

在 APP 的新增点位设置界面：

1. 移动机器人到门口拍照姿态；
2. 点击 **获取当前坐标**。下方状态条绿色表示成功，红色表示失败；失败时不保存，重新获取；
3. 确认地图编号与当前激活地图一致；
4. 点位类型选择 **任务点**；
5. 步态选择当前固件和现场地面条件允许的类型；首次仅选基础步态；
6. 导航模式选择 **自主导航**；
7. 运动速度选择 **低速**；
8. 运动方向选择 **前进**；
9. 开启 **障碍物检测**，按钮应蓝色高亮；
10. 保存当前点位和路线。

记录：

```text
点位名称：门口拍照点

坐标获取：成功 / 失败
```

### 7.3 任务点 2：自主充电点

5. 记录当前 APP 显示的步态、导航模式、速度、方向和障碍物检测设置；

### 7.4 路线保存与遥控器导航模式测试

1. 保存路线；
2. 在 APP 控制界面点击 **使用模式**，切换到 **导航模式**；
3. 确认机器人进入导航模式，且未出现异常保护；
4. 打开标点工具路线列表；
5. 选择只包含“门口拍照点”的测试路线；

7. 由操作员、安全观察员共同复核路线预览、地图编号、任务点、低速、前进和障碍物检测；
8. 点击 **执行** 启动路线；执行中再次点击 **执行** 可停止路线；
9. 到达门口拍照点后，执行 APP 拍照并记录结果；
10. 不将充电点加入本次执行路线，不执行一键充电。

### 9.2 代码核查结论

已核查当前仓库代码：

- `backend/app/protocol/frame.py` 已实现 16 字节 APDU 的离线编码、解码和增量拆包/粘包处理；`m20_v010_layout()` 按受控《山猫 M20 系列软件开发手册》V0.1.0 第 6–8 页使用同步字 `EB 91 EB 90`、小端长度/报文 ID、JSON/XML 格式位和 7 字节零保留字段。该布局尚未作为《软件开发指南》V1.2.1或当前固件的实机协议事实确认，真实接入前必须用 V1.2.1 原文、当前固件和厂商样本复核。
- `backend/app/protocol/messages.py` 已实现 `PatrolDevice` JSON/XML 通用信封编解码；`backend/app/navigation/v010.py` 仅离线构造 `1003/1`、`1004/1`、`1007/1` 报文并执行本地门控，尚无基于真实响应的任务状态机。
- `backend/app/robot/basic_client.py` 提供受证据门控的 TCP 客户端原语，但当前部署服务不启用真实连接、心跳、状态订阅、导航发送或取消。`backend/app/dashboard.py` 只提供 `SIMULATED`、`connected=false`、`control_enabled=false` 的本地只读页面，并强制绑定 `127.0.0.1`。

因此，当前代码与本文件“本次只通过遥控器/APP 测试、二次开发暂不启用”的描述一致。当前不需要为下午测试修改机器人控制代码，也不能把离线协议编解码视为已完成实机导航功能。
