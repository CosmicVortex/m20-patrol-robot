## 2. 问题分类与解决方案

### 场景A: TCP连接失败

**症状**:
```json
{
  "source": "NO_DATA",
  "connected": false,
  "tcp_connected": false,
  "error_message": "连接到 10.21.31.103:30001 超时"
}
```

**可能原因**:
1. AOS主机未开机或网络断开
2. IP地址已变更（当前配置: 10.21.31.103）
3. 防火墙阻止TCP 30001端口
4. AOS basic_server服务未运行

**排查步骤**:
```bash
# 1. 检查AOS主机状态
ping -c 3 10.21.31.103

# 2. 扫描局域网找AOS（如果IP可能变更）
for i in {100..120}; do
    ping -c 1 -W 1 10.21.31.$i 2>/dev/null && echo "10.21.31.$i 在线"
done

# 3. 检查本地服务
pgrep -f "backend.app.server" && echo "服务运行中" || echo "服务未运行"

# 4. 查看防火墙规则
sudo iptables -L INPUT -n | grep 30001
```

**解决方案**:
```bash
# 更新IP配置（如果找到新IP）
cd ~/m20-patrol-robot
sed -i 's/"10.21.31.103"/"新IP地址"/' deploy/readonly-manifest.json
bash deploy/scripts/deploy-readonly.sh --one-shot

# 或重启服务
systemctl --user restart m20-patrol-readonly.service
```

### 场景B: TCP连接成功但无数据推送

**症状**:
```json
{
  "source": "REAL",
  "connected": true,
  "tcp_connected": true,
  "valid_frames": 0,
  "bytes_received": 0
}
```

**根因分析**:
根据官方文档 V1.2.1 §3.2：
> **basic_server 以心跳来源的 IP/端口作为目标地址，向客户端主动推送数据**

**问题核心**:
1. GOS可能未持续发送心跳（已修复）
2. AOS未将GOS IP记录为有效客户端
3. 需要重新建立连接触发推送

**排查步骤**:
```bash
# 1. 检查心跳日志
journalctl --user -u m20-patrol-readonly.service -n 50 --no-pager -l | grep -E "心跳|遥测"

# 2. 在AOS上检查连接（需要SSH）
ssh user@10.21.31.103 "netstat -an | grep 30001"

# 3. 查看详细诊断
python3 deploy/scripts/diagnose-deep.py
```

**解决方案**:
```bash
# 强制重新连接（最常用）
systemctl --user stop m20-patrol-readonly.service
sleep 2
systemctl --user start m20-patrol-readonly.service
sleep 3

# 验证数据恢复
curl -s http://127.0.0.1:8080/api/v1/health
```

### 场景C: 数据解析失败

**症状**:
```json
{
  "source": "ERROR",
  "valid_frames": 0,
  "invalid_frames": > 0,
  "error_message": "Parse error: ..."
}
```

**可能原因**:
1. APDU帧格式不匹配
2. JSON解析错误
3. 字段映射不完整

**排查步骤**:
```bash
# 查看详细错误日志
journalctl --user -u m20-patrol-readonly.service -n 100 --no-pager -l | grep -i "error\|fail\|parse"

# 检查固件版本（需要SSH到AOS）
ssh user@10.21.31.103 "cat /opt/aos/version.txt"
```

**解决方案**:
参考 [官方协议对照](#3-官方协议对照) 章节验证APDU格式。

## 3. 官方协议对照

### 3.1 APDU帧结构（V1.2.1 §1.1.5）

```
┌─────────────────────────────────────────────┐
│          协议头部 (16 字节)                    │
├──────┬──────┬──────┬──────┬──────┬──────┬───┤
│ 同步 │ 同步 │ 同步 │ 同步 │ 长度 │ 报文ID│格式│
│0xeb  │0x91  │0xeb  │0x90  │(2B)  │(2B)  │(1B)│
└──────┴──────┴──────┴──────┴──────┴──────┴───┘
                                    │
                                    ▼
┌─────────────────────────────────────────────┐
│              ASDU (N 字节)                    │
│            (JSON 格式)                        │
└─────────────────────────────────────────────┘
```

**字段说明**:
- 同步字符: `0xEB 0x91 0xEB 0x90`（固定）
- 长度: 2字节小端，ASDU字节段长度
- 报文ID: 2字节小端，请求方控制
- 格式: 1字节 (`0x00`=XML, `0x01`=JSON)
- 预留: 7字节（填0）

### 3.2 心跳机制（V1.2.1 §3.1）

**官方要求**:
> 客户端均应以不低于 **1Hz** 的频率发送任意指令作为心跳；服务端超过 **2s** 未收到客户端任何请求则认为客户端离线，**停止向该客户端推送所有主动上报数据**。

**心跳格式**:
```json
{
  "PatrolDevice": {
    "Type": 100,
    "Command": 100,
    "Time": "2026-08-16 10:00:00",
    "Items": {}
  }
}
```

**实现要点**:
- 发送频率: 推荐 2Hz（每0.5秒）
- 超时判定: 超过 2s 未收到心跳则断开
- 建议客户端超过 3s 未收到响应则判定服务端断连

### 3.3 主动推送数据（V1.2.1 §3.2）

| Type | Command | 频率 | 内容 |
|------|---------|------|------|
| 1002 | 3 | 事件驱动 | 异常状态 |
| 1002 | 4 | 10Hz | 运控状态：姿态、速度、16关节 |
| 1002 | 5 | 2Hz | 设备状态：电池、温度、GPS |
| 1002 | 6 | 2Hz | 基础状态：运动状态、充电状态 |

**订阅方式**:
- TCP: 建立连接后自动接收
- UDP: 需先发送查询请求触发推送

### 3.4 运动状态映射（V1.2.1 §1.2.3）

| 值 | 含义 |
|----|------|
| 0 | 空闲 |
| 1 | 站立 |
| 2 | 关节阻尼/软急停 |
| 3 | 开机阻尼 |
| 4 | 趴下 |
| 17 | RL控制 |

### 3.5 步态映射（V1.2.1 §1.2.4）

| 值 | 含义 |
|----|------|
| 4097 (0x1001) | 基础(标准) |
| 4098 (0x1002) | 高台(标准) |
| 12290 (0x3002) | 平地(敏捷) |
| 12291 (0x3003) | 楼梯(敏捷) |

## 5. 常见问题排查

### Q1: 部署后仍然显示"NO_DATA"

**排查清单**:
- [ ] TCP连接是否成功？
- [ ] 心跳是否正常发送？
- [ ] AOS是否返回主动推送数据？
- [ ] 服务日志是否有错误？

**快速修复**:
```bash
systemctl --user restart m20-patrol-readonly.service
sleep 3
curl -s http://127.0.0.1:8080/api/v1/health
```

### Q2: 数据偶尔中断

**可能原因**:
- 网络不稳定
- 心跳超时（默认3秒）
- AOS服务重启

**排查**:
```bash
# 查看重连次数
journalctl --user -u m20-patrol-readonly.service -n 200 --no-pager | grep -c "重新连接"

# 查看详细日志
journalctl --user -u m20-patrol-readonly.service -f
```

### Q3: 状态显示"未知"或映射错误

**原因**: 前端状态映射与V1.2.1标准不一致

**解决**: 已修复，确保使用最新代码：
```bash
git pull
bash deploy/scripts/deploy-readonly.sh --one-shot
```

### Q4: 巡检距离始终为0

**原因**: 后端缺少distance字段解析

**解决**: 已修复，`status.py`已添加`distance`字段映射。
