## P0 - 关键问题（导致数据不显示）

### 问题1: `loop_count` 字段来源错误
- **位置**: `backend/app/robot/status.py` 第232-237行, `_parse_navigation_status()`
- **现象**: 前端仪表盘显示的"圈数"始终为0
- **根因**: `loop_count` 字段在V1.2.1规范中属于**导航异常状态上报**(Type=1007, Command=3)，但当前代码只从导航任务状态查询(Type=1007, Command=1)中解析数据
- **数据流**: 
  - `_parse_navigation_status()` → 返回 `{value, status, error_code, error_message}` (无 `loop_count`)
  - `_parse_navigation_abnormal()` → 返回包含 `loop_count` 的完整结构
  - 前端 `_updateMetrics()` 从 `d.nav_status?.loop_count` 读取 → 始终为0
- **修复建议**:
  ```python
  def _parse_navigation_status(message):
      items = message.items
      return StatusResult("navigation_status", {
          "value": items.get("Value"),
          "status": items.get("Status"),
          "error_code": items.get("ErrorCode", 0),
          "error_message": NAV_ERROR_CODES.get(items.get("ErrorCode", 0), "Unknown"),
          "loop_count": items.get("LoopCnt", 0),  # 添加此字段
          "remaining_count": items.get("RemainingCnt"),  # 可选
      })
  ```

### 问题2: 缺少 `distance` 字段导致距离统计为0
- **位置**: `docs/website/js/views/dashboard.js` 第500-505行
- **现象**: "巡检距离"和"总距离"始终显示0.0
- **根因**: 前端读取 `robot.position.distance`，但后端position对象不包含此字段
- **数据流**:
  - `_parse_position()` 返回 `{location, pos_x, pos_y, pos_z, roll, pitch, yaw}` (无 `distance`)
  - `_parse_navigation_abnormal()` 返回的 `location_status` 也不包含 `distance`
  - 前端: `if (inspectedEl && robot.position?.distance)` → 条件不成立，不更新显示
- **修复建议**: 
  - 方案A: 后端在position数据中添加累计距离字段（需要设备支持）
  - 方案B: 前端改用 `remain_mile` 字段并反向计算已行驶距离
  - 方案C: 在前端维护距离累加器，基于 `linear_x`/`linear_y` 积分计算

### 问题3: 连接状态显示不明确
- **位置**: `docs/website/js/views/dashboard.js` 第156-168行
- **现象**: 当TCP连接失败时，前端仅显示"NO DATA / WAITING"，无法区分是"等待连接"还是"连接失败"
- **根因**: `_updateConnectionBadge()` 只检查 `source` 和 `connected`，未考虑 `error_message` 字段
- **修复建议**:
  ```javascript
  if (source === 'REAL' && connected) {
    // ...现有逻辑
  } else if (source === 'ERROR') {
    badge.className = 'status-badge blocked';
    badge.textContent = `ERROR: ${robot.error_message || '通信失败'}`;
  } else if (source === 'STALE') {
    badge.className = 'status-badge warn';
    badge.textContent = 'STALE / RECONNECTING';
  } else {
    // NO_DATA / WAITING
  }
  ```

## P1 - 重要问题（影响用户体验）

### 问题4: 速度计算可能显示误导值
- **位置**: `docs/website/js/state-manager.js` 第180-182行
- **现象**: 当motion数据为空时，速度显示为0而非"无数据"
- **根因**: `Math.sqrt((0)**2 + (0)**2) = 0`，无法区分"静止"和"无数据"
- **修复建议**: 增加空数据检查，当motion对象为空时返回null

### 问题5: `telemetry_tx_enabled` 配置未真正控制心跳发送
- **位置**: `backend/app/robot/telemetry.py` 第188行
- **现象**: 即使设置 `telemetry_tx_enabled=False`，心跳仍会发送
- **根因**: `transmit_enabled=True` 硬编码在 `_run_loop()` 中，未读取 `self.config.telemetry_tx_enabled`
- **影响**: 诊断标志与实际行动不一致
- **修复建议**: 使用 `self.config.telemetry_tx_enabled` 控制是否发送心跳

### 问题6: 错误提示不够详细
- **位置**: `backend/app/robot/basic_client.py` 第154-159行
- **现象**: 连接失败时错误信息较简略
- **修复建议**: 
  - 超时: 提示检查网络或AOS服务状态
  - 拒绝: 提示检查端口30001是否开放
  - 其他: 添加系统级错误信息

## 数据流完整性结论

### ✅ 正常数据流路径
```
TCP 30001 ← AOS基本服务器
    ↓
BasicServerClient.connect() 
    ↓
receive_messages() → decode_patrol_message() → parse_status_message()
    ↓
TelemetryAdapter._process_message() → _update_snapshot_inner()
    ↓
get_status_payload() → /api/v1/status/latest
    ↓
ApiService.fetchStatus() → StateManager.updateTelemetry()
    ↓
DashboardView._updateDashboard()
```

### ✅ 协议对齐确认
- 协议头部: 16字节，同步字符 `0xEB91EB90` ✓
- ASDU格式: JSON `{"PatrolDevice": {...}}` ✓
- 消息类型: Type 100/Command 100 (心跳) ✓
- 状态消息: Type 1002/Command 6,4,5,3 ✓
- 导航消息: Type 1003/1, 1004/1, 1007/1, 1007/2, 1007/3, 2002/1 ✓

### ⚠️ 需要验证的假设
1. 设备是否实际发送 `loop_count` 在导航状态查询响应中
2. 设备是否在position数据中包含累计距离字段
3. AOS服务是否在TCP连接后持续推送数据（需≥1Hz心跳）
