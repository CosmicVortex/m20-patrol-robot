# M20 Pro 巡逻项目需求基线

版本：0.1
状态：开发基线；本轮增加双场地资产模型，仍未包含导航实机放行
更新：2026-08-06

## 1. 目标与边界

第一阶段以山猫 M20 Pro 为演示平台，业务程序部署在 GOS。AOS 继续负责运动控制和 `basic_server`，NOS 继续负责建图、定位和导航。项目程序不得修改 AOS/NOS 原厂服务、网络路由或 NOS 原始地图。

建图采用两个独立阶段：先在华翔智行办公室完成办公室地图并验证自主巡逻导航，再在东莞中升之星奔驰 4S 店重新建图并生成门店专用地图。办公室地图、地图包和点位不得直接带入门店；每个场地必须记录独立地图身份和整包 SHA-256。

当前视频源阶段只登记机器狗本体前后相机。数尔安防开发软件属于后续独立适配项，在取得真实接口、流地址、编码和权限证据前不得写入可用配置。

本阶段的交付顺序：

1. 先完成可重复的离线协议验证和只读状态模型；
2. 再完成 GOS 只读部署、现场环境核验和数据样本采集；
3. 在真实版本、协议权限、定位和安全条件确认后，在华翔智行办公室完成真实状态、视频和受控导航接入；
4. 办公室阶段必须通过 Web 人工控制单点导航、实时状态显示和前后相机切换显示；
5. 办公室功能和安全验收全部通过后，才迁移至东莞中升之星奔驰 4S 店重新建图和验收。

## 2.1 双场地验收顺序

1. 华翔智行办公室：现场建图、整包备份、哈希记录、定位核验、单点自主导航和无控制视频取证；
2. 办公室回归：使用同一地图完成重复路线、异常停止和恢复记录；
3. 东莞中升之星奔驰 4S 店：清理办公室资产引用，重新建图并单独备份，重新采集点位；
4. 门店回归：在门店地图上重新完成定位、路线和视频验收；
5. 只有两地证据齐全后，才评审多点巡逻任务编排和后续 S10 迁移。

地图资产不以文件名作为身份依据，必须以现场核验的地图身份、生成时间、场地和整包 SHA-256 联合记录。

## 2.2 华翔智行办公室阶段必须完成的功能

办公室阶段必须在现场安全放行下完成完整闭环：

1. 依据 V0.0.1 手册在 NOS 完成办公室地图；
2. 通过官方遥控器/APP 完成自主导航单点基线；
3. 二次开发程序采集并显示 M20 Pro 主机、软件/固件和运行状态；
4. 接入 AOS 本体前后相机，经 GOS 视频代理或转码后在 Web 端切换显示；
5. 授权操作员通过 Web 人工发起、停止和取消单点导航；
6. Web 端显示连接、定位/地图、导航任务、异常保护、电量和视频状态；
7. 定位丢失、通信超时、急停、保护故障、低电量或人员进入区域时自动拒绝/暂停；
8. 单点导航、取消、状态、视频切换、异常停止和恢复形成现场记录；
9. 全部通过后，才允许迁移至东莞门店重新建图。

## 3. 验收规则

### 3.1 当前可验收范围

- `PYTHONPATH=. uv run --with pytest pytest -q` 全部通过；
- APDU/ASDU 测试不建立网络连接，不发送机器人报文；
- 模拟页面返回 `source=SIMULATED`、`connected=false`、`control_enabled=false`；
- 部署脚本默认不启用机器人控制，服务只绑定回环地址；
- 文档不把文档事实、现场事实和推断混为一谈。

### 3.2 真实接入前置条件

以下条件全部满足前，不得建立 AOS 长连接、发送心跳或下发导航：

- M20 Pro 实际型号、系统/固件版本和主机身份已由现场输出确认；
- V1.2.1、V0.1.0 和当前固件的差异已记录；
- basic_server 第三方连接权限和真实脱敏样本已取得；
- 地图、定位、异常、急停和电量状态均可读且可判定新鲜度；
- 现场隔离区、操作员、安全观察员和停止流程已确认；
- 现场负责人书面放行。

## 4. 需求驱动检查

每次代码或文档变更必须能回答：

1. 变更对应哪个需求编号？
2. 变更增加了什么可验证行为？
3. 测试、证据和回滚方式是什么？
4. 是否引入了未批准的设备访问或控制能力？
5. 文档是否仍与实际代码一致？

无法关联到需求编号、验收证据或安全边界的工作，放入归档计划，不进入当前交付。

## 5. 当前结论

当前工作严格按需求驱动推进的部分是 R-01 至 R-05：先做离线、只读和可回滚基础。R-06 至 R-10 仍是后续需求，尚未具备开发和实机验收条件。目标是形成可在 M20 Pro GOS 上一键安装的**只读/模拟基线**；这不等同于已经具备一键部署真实导航系统的能力。
